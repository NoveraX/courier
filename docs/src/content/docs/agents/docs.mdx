## The docs of the version you install

What the agent in your editor knows of Courier may be older than the Courier your project installs: an option renamed, a default changed, a page that moved. `@noverax/courier-docs` holds the documentation of the version it is released with — every page of this site, as the Markdown the site serves at the page's address with `.md` after it — for the agent to read from your project, with no network:

```bash
npm install --save-dev @noverax/courier-docs
```

It is released with every other Courier package, at the same version, so updating Courier updates the docs the agent reads.

## What the folder holds

The pages are in `node_modules/@noverax/courier-docs/docs/`, one Markdown file a page, where the site has them: `core-concepts/caller.md` is [/docs/core-concepts/caller](/docs/core-concepts/caller).

| File | What it holds |
| --- | --- |
| `index.md` | Every page by section, each with a link to its file and what it covers: where an agent starts |
| `<page>.md` | A page, as the site serves it as Markdown: its title and description on top, its code as written |
| `manifest.json` | The version the docs are for, and each page's title, section and address on the site, with its headings, their anchors and the lines they are on |

A link in a page to `/docs/<page>#<anchor>` names `<page>.md` in the folder and one of its headings: `manifest.json` lists each heading with the anchor the site gives it.

## Point your agent at them

Agents read `AGENTS.md`, at your project's root, when they start. Courier's block in it tells yours where the docs are. Setting Courier up writes it if you say so — in a terminal it asks, and `--agents-md` answers yes — and installs `@noverax/courier-docs` with it: `npx @noverax/create-courier --agents-md` for a new project, `npx @noverax/courier-cli setup --agents-md` for one that has Courier already. Or add the block as it stands:

```markdown title="AGENTS.md"
<!-- BEGIN:courier-agent-rules -->
## Courier in this project

Courier changes between versions, and its APIs may differ from what you know of it. Before writing or changing code that uses an `@noverax/*` package, read the relevant page of the documentation installed with this project, in `node_modules/@noverax/courier-docs/docs/`: `index.md` lists every page, and they match the installed version. In a monorepo, look in the `node_modules` of the package that uses Courier.

Courier keeps this block up to date while it is here, and leaves the rest of this file alone. Delete the block, markers included, and nothing writes it again.
<!-- END:courier-agent-rules -->
```

Studio, as it starts, brings the block up to date for the Courier it runs with — the text between its markers, in an `AGENTS.md` that has them — and so does `courier-cli upgrade`. Both leave the rest of the file alone, as they leave a file without the block.

## Search and read them as tools

An agent that works through tools rather than files gets the same docs from an MCP server the package runs over stdio, offline:

```bash
claude mcp add courier-docs --scope project -- npx @noverax/courier-docs mcp
```

In Cursor or VS Code, add the same command to `.cursor/mcp.json` or `.vscode/mcp.json`, as [In Your Editor](/docs/agents/editor#add-it-to-your-editor) shows for `courier-mcp`.

| Tool | What it does |
| --- | --- |
| `docs_search` | The parts of the docs that answer a question — a feature, an export's name, an option, an error's code — best first: each the part of a page under one heading, with the lines that match, and at most two parts of one page. `limit` takes 1 to 10, 5 by default. |
| `docs_read` | A page as Markdown, or the part of it under one heading, by its heading's words or its anchor: the page as `docs_search` or `docs_list` names it, or as a link in another page does, `/docs/<page>#<anchor>`. A page longer than 32,000 characters comes in pieces, each saying where the next one starts. |
| `docs_list` | Every page by section, with what it covers. |

Each answer names the version the docs are for.

## Over the network

An agent that fetches pages rather than reading files gets the same Markdown from this site:

- every docs page at its address with `.md` after it: [/docs/quick-start.md](/docs/quick-start.md);
- every docs page at its own address too, to a request whose `Accept` asks for `text/markdown` — named outright, and counting for more than `text/html`, as nextjs.org reads it. A shared cache keeps only the page, never that answer, so one between the agent and the site may answer with the page: the address with `.md` after it is Markdown whatever is asked;
- [/llms.txt](/llms.txt), every page by section with what it covers, and [/llms-full.txt](/llms-full.txt), the whole documentation in one file.

The site serves the documentation of the latest release; the package, that of the version you install.
