## Recommended file structure

Keep your API definitions separate from your UI code. The structure is the same regardless of framework:

```bash
src/
├── api/
│   ├── index.ts          # defineApi + sources export
│   ├── users.ts          # users group (defineGroup)
│   ├── posts.ts          # posts group
│   └── files.ts          # files group
├── lib/
│   └── caller.ts         # createCaller / createProxyCaller / createProxyQueryCaller
├── app/                  # (Next.js) or pages/ (Nuxt) or routes/ (SvelteKit)
│   ├── api/
│   │   └── request/
│   │       └── route.ts  # proxy route handler
│   └── ...
└── server/               # (if using Express/Hono/Fastify separately)
    └── index.ts
```

## Source definitions

The `api/` directory contains your API structure. Each group lives in its own file:

```ts title="api/users.ts"
import { courier, defineGroup } from "@noverax/courier/define"

const { query, mutation } = courier()

type User = { id: string; name: string; email: string }

export const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: query.response<User[]>().via((http) => http.get()),
    getById: query
      .variables<{ id: string }>()
      .response<User>()
      .via((http, vars) => http.get(":id", vars)),
    create: mutation
      .variables<{ name: string; email: string }>()
      .response<User>()
      .via((http, vars) => http.post("", vars)),
    update: mutation
      .variables<{ id: string; name: string }>()
      .response<User>()
      .via((http, vars) => http.put(":id", vars)),
    remove: mutation
      .variables<{ id: string }>()
      .response<null>()
      .via((http, vars) => http.del(":id", vars)),
  },
})
```

The main file combines groups into an API source:

```ts title="api/index.ts"
import { defineApi } from "@noverax/courier/define"
import { users } from "./users"
import { posts } from "./posts"
import { files } from "./files"

const api = defineApi({
  baseURL: process.env.API_URL!,
  groups: { users, posts, files },
})

export { api }
```

<Callout variant="tip" title="One group per file">
Keeping each group in its own file makes it easy to find and modify endpoints. Types stay co-located with the endpoints that use them.
</Callout>

## Caller setup

Create the appropriate caller for your use case:

```ts title="lib/caller.ts (React Query)"
import { createProxyQueryCaller } from "@noverax/courier-react"
import { api } from "@/api"

export const { useQuery, useMutation, useSuspenseQuery, caller } = createProxyQueryCaller<typeof api>()
```

```ts title="lib/caller.ts (Vanilla / Vue / Svelte)"
import { createProxyCaller } from "@noverax/courier"
import { api } from "@/api"

export const caller = createProxyCaller<typeof api>("api", { source: api, proxyPath: { http: "/api/request" } })
```

```ts title="lib/server-caller.ts (Server-side)"
import { createCaller } from "@noverax/courier"
import { api } from "@/api"

export const caller = createCaller(api)
```

## Multiple backends

Define a separate `defineApi` for each backend service:

```ts title="api/index.ts"
import { defineApi } from "@noverax/courier/define"
import { users, posts } from "./groups"
import { auth } from "./auth"

const mainApi = defineApi({
  baseURL: process.env.API_URL!,
  groups: { users, posts },
})

const authApi = defineApi({
  baseURL: process.env.AUTH_API_URL!,
  groups: { auth },
})

export { mainApi, authApi }
```

Create separate callers for each API, with full type inference:

```ts
const mainCaller = createCaller(mainApi)
const authCaller = createCaller(authApi)

const users = await mainCaller.users.getAll()
const token = await authCaller.auth.login({ email, password })
```

## Environment variables

Backend URLs should always be server-side environment variables:

```bash title=".env.local"
API_URL=http://localhost:4000
AUTH_API_URL=http://localhost:5000
```

<Callout variant="warning" title="Never expose API_URL to the client">
In proxy mode, the browser only talks to `/api/request`. Your backend URL, API keys, and other secrets stay on the server.
</Callout>
