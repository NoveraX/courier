This release changes how a call fails, what a retry policy repeats, which headers a request carries, how realtime connects, how the proxy reads a request body, how variables are written into a request, whether an endpoint addressed with `.via()` reads or writes, where the options only a server reads are checked, and what Studio writes for an import. Each row pairs what 0.4 did, or what code written for it says, with what holds now. The pages each section links to describe the current API alone.

## Run the Upgrade

```bash
npx @noverax/courier-cli@latest upgrade --dry-run  # show what it changes
npx @noverax/courier-cli@latest upgrade            # make the changes, once you say yes
```

In a project, or in a workspace from any of its packages, it moves every one of Courier's packages to the new release at once: each range raised in the kind of range it is written in — one of another kind is left as written, and the plan says why — and one install with your package manager. The plan comes first, with each section of this page the upgrade crosses. When the install fails, or you press Ctrl+C, the manifests, the lockfile and your code are put back as they were; once it is done, the types of what it changed are checked. With `--yes` it goes ahead without asking, and refuses a project whose changes git has not committed unless `--allow-dirty` is passed. Where no manifest lists `@noverax/courier-docs`, the plan names `npx @noverax/courier-cli setup --agents-md`, which installs this release's docs and points your editor's agent at them — see [Docs for Your Agent](/docs/agents/docs). Run it with `@latest`: it knows the changes up to its own release, and refuses to move to a newer one.

It changes your code only where the code says for certain what it means: through the names a file imports from Courier's packages and the heads of `courier()` an endpoint's chain starts from, the script blocks of Vue, Svelte and Astro components among the files. A file Studio wrote is left to Studio, which tells your edits to an endpoint from its own by what it wrote: **Regenerate files**, in the import's **Manage**, writes it as this release's Studio does, and the plan names each such file the release changes.

| 0.4 | Changed to |
|---|---|
| `AuthError`, `ForbiddenError`, `RateLimitError`, `fromErrorCode` and `isRealtimeError` from `@noverax/courier` | the same names from `@noverax/courier/realtime` |
| `TimeoutError`, 0.4's realtime timeout, from either entry | `RealtimeTimeoutError` from `@noverax/courier/realtime` |
| `SSESubscription` | `Subscription` |
| `sendAuthRequired(connections, id, ms)` as a statement of an async function | `await connections.requireAuth(id, { timeoutMs: ms })` |
| `0` in `retryOn`, of `retryMiddleware` or of an endpoint's `.retry()` | `"network"` and `"timeout"` |
| `isHTTPError(error) && error.status === 0`, where the file binds `isHTTPError` only by its import | `isNetworkError(error) \|\| isTimeoutError(error)`, the two imported in place of `isHTTPError`, or beside it where the file still uses it |
| `.via(closure).reads()`, where the closure is written there, calls `get`, `head`, `options` or `query` alone, and neither it nor its wire is typed | `.via(closure)` |
| `.via(closure)`, where such a closure calls a reading verb and a writing one, and no kind is named after it | `.via(closure).writes()`: the write 0.4 took it for |
| `"PROXY_VARIABLE_NOT_SERIALIZABLE"`, a string that holds the code alone | `"VARIABLE_NOT_ENCODABLE"`, in the string's own quotes |
| An import of `@noverax/courier` in a file a page loads, whose names `@noverax/courier/client` gives — `createCaller` among them only where no server loads the file | the same import from `@noverax/courier/client` |
| An import of `@noverax/courier` in a file only the server loads, whose names `@noverax/courier/server` gives | the same import from `@noverax/courier/server` |

A renamed name is renamed at every reference only where the file binds it once and nothing takes the new name; otherwise it is imported under its old name, with `as`. What it finds and cannot change for certain, it lists at its line with what to write instead: a check of status 499 or of `error.data.code`, `new HTTPError({ status: 0 })`, a platform's `AbortError`, `onError` typed with `HTTPError`, a `retryOn` function, a `sendAuthRequired()` whose value is used or that is outside an async function, 0.4's calls of `connections` and `sseConnections`, the client's `ws.heartbeat` and `ws.maxMessageSize`, a pub/sub adapter of your own, an `allowedHosts` entry with a scheme, a `.via()` endpoint that names no kind whose closure calls reading verbs alone, and so reads now, a closure typed `HttpProbe<Variables>`, a key or a member named `PROXY_VARIABLE_NOT_SERIALIZABLE`, a URL import's `pinHash`, an import's `from` with a user, a password or a secret parameter in its address — shown without them, with the environment variables to read them from — and an import of `@noverax/courier` that stays in the root: one with `createCaller` in a file the server loads too, a page's of the server's names or of the root whole, one in a package a page loads by its name whose entry the upgrade could not follow to its code, and one in a file whose side neither the framework nor the imports tell. Code it cannot read for certain — a name taken through a namespace import, a call through a variable, an endpoint whose head another file takes from `courier()`, an address the config computes — it neither changes nor lists, and the other rows of this page are yours to check against your code and your deployment.

## Call Errors

A call that got no successful answer rejects with an `HTTPError` when an answer came, a `NetworkError` when none did and a `TimeoutError` when its time ran out, and a cancelled call with Courier's `AbortError` — see [NetworkError, TimeoutError & AbortError](/docs/api/call-errors).

| 0.4 | Now |
|---|---|
| `isHTTPError(error) && error.status === 0` | `isNetworkError(error) \|\| isTimeoutError(error)` |
| `error.data.code === "TIMEOUT"` | `isTimeoutError(error)` |
| `error.data.code` — the system's code | `error.systemCode` |
| `new HTTPError({ status: 0, … })` in a mock or a test | `new NetworkError({ cause })`: `new HTTPError()` refuses a status outside 100 to 599 with a `RangeError` |
| An answer the browser hides — `mode: "no-cors"`, a redirect it was told not to follow — read as status 0 | `ConfigurationError` `RESPONSE_OPAQUE` |
| `onError: (error: HTTPError) => …` | `onError: (error: RequestFailure) => …` — an `HTTPError`, a `NetworkError` or a `TimeoutError` |
| `error instanceof DOMException && error.name === "AbortError"` | `isAbortError(error)` |
| `error === reason`, the reason the signal was given | `isAbortError(error) && error.cause === reason` |
| `isHTTPError(error) && error.status === 499`, a call a newer one superseded | `isAbortError(error) && error.code === "SUPERSEDED"` |

A check of `error.name === "AbortError"` still holds, as Courier's `AbortError` is named so, and an upstream's own answer of status 499 is an `HTTPError` like any other. A cancellation is no failure: `onError` is not told of it, and no retry repeats it.

## Retries

A retry policy repeats what an upstream may get over, waits a random time between attempts, and shares a budget with the calls it retries — see [retryMiddleware](/docs/middleware/built-in#retrymiddleware). The query hooks leave retries to it.

| 0.4 | Now |
|---|---|
| Without `retryOn`, a timeout retried | not retried unless `retryOn` names `"timeout"` |
| Without `retryOn`, every 5xx retried, `501` among them | `500`, `502`, `503` and `504` retried, and `408`, `425` and `429` |
| `retryOn: [0, 503]` | `retryOn: ["network", "timeout", 503]` |
| `retryOn: (response) => response.status === 503` | `retryOn: (failure) => failure.kind === "status" && failure.status === 503` |
| Waits of exactly the backoff, doubling from 300 ms with no ceiling | a random wait up to it, never past `maxDelay`, 20 s; `jitter: "none"` waits it exactly |
| `Retry-After` unread | waited, in seconds or as a date; an answer that asks for longer than `maxDelay` is not retried |
| A `limit` of any size | at most 10 |
| An option the policy does not have — `attempts`, `retries`, `backoff: 300` — ignored | `ConfigurationError` `RETRY_OPTIONS_INVALID`: the options are `limit`, `delay`, `backoff: "fixed"` or `"exponential"`, and the others the reference lists |
| An endpoint's `.retry()` taken as written | checked on the endpoint's first call, refused with the same code |
| `useQuery`, `useSuspenseQuery`, `useInfiniteQuery` and `useComputedQuery` retrying a failed call three times | no retries of their own: the API's `.retry()` or `retryMiddleware` repeats a call, or `defaultOptions.queries.retry` on the `QueryClient` keeps the hooks' |

## Headers

A request's headers are put together in one place, which refuses a value no request can carry before anything is sent — see [Options Reference](/docs/advanced/options) and [authMiddleware](/docs/middleware/built-in#authmiddleware).

| 0.4 | Now |
|---|---|
| A header value with a NUL or a line break inside it, refused by the platform with a `TypeError` that repeats the value | `ConfigurationError` `HEADER_VALUE_INVALID`, naming the header and not its value, before anything is sent; a character past U+00FF too |
| A header value with another control character, such as a vertical tab, refused by the dispatcher as it sends: an `HTTPError` of status 0, and retried | `ConfigurationError` `HEADER_VALUE_INVALID` before anything is sent, and not retried |
| `authMiddleware` with no token sending `Bearer undefined`, or `Bearer` for `""` | no header; `required: true` refuses the call with a `MissingTokenError` before it is sent |
| `authMiddleware` taking an option it does not have, a `header` that is no header name, or a `scheme` that is no scheme | `ConfigurationError` `AUTH_OPTIONS_INVALID` where the middleware is made |
| An `allowedHosts` entry with a scheme, a path or a user, matching nothing | `ConfigurationError` `INVALID_ALLOWED_HOST` where the handler is made |

## Realtime

### On the Server

`connections` and `sseConnections` name connections by a selector — an id, `{ id }` with up to 1000 of them, or `{ meta }` — and reach them on every replica that shares the pub/sub adapter — see [A User's Connections, on Every Replica](/docs/deployment/replication#a-users-connections-on-every-replica).

| 0.4 | Now |
|---|---|
| `connections.disconnect(id, code, reason)` | `await connections.disconnect(id, { code, reason })` |
| `connections.disconnectByMeta((meta) => meta.userId === id, code, reason)` | `await connections.disconnect({ meta: { userId: id } }, { code, reason })` |
| `connections.getByMeta(predicate)` | `connections.list({ meta: { … } })`, or `list().filter(…)` for any other test |
| `sendAuthRequired(connections, id, ms)` | `await connections.requireAuth(id, { timeoutMs: ms })` |
| `sseConnections.getByMeta(predicate)` | `sseConnections.list({ meta: { … } })` |
| `sseConnections.disconnect(id, reason)` | `await sseConnections.disconnect(id)`, or a selector |
| `sseConnections.disconnectAll(reason)` | `sseConnections.disconnectAll()` |
| `sseConnections.broadcastToMeta(predicate, event)` | `sseConnections.broadcastToMeta({ userId }, event)` |
| A pub/sub adapter of your own | implements `state`, `onStateChange()` and `stats()`, takes a subscription without waiting on its server, queues what is published while it is not ready within bounds, and rejects `publish()` and `subscribe()` only once disconnected; the adapters Courier ships need nothing done |
| Handlers of one process sharing `createMemoryPubSub()`, which delivered nothing | `createMemoryBus()`, each handler on `bus.replica(name)`; `createMemoryPubSub()` is one replica alone |

### In the Client

Every subscription, stream and channel is one `Subscription` object, and a connection runs on one state machine — see [Streams & Channels](/docs/advanced/realtime).

| 0.4 | Now |
|---|---|
| `SSESubscription` | `Subscription`, from `@noverax/courier/realtime`; `WSChannel` extends it |
| A subscription written by hand | needs `on()` for `data`, `error`, `status`, `open` and `close`, `reconnect()` and `dropped` |
| `on()` with an event the subscription does not have, taken | refused by its types, and with `ConfigurationError` `UNKNOWN_EVENT` as it runs |
| A channel `connected` once its socket opened | once the server confirmed its subscribe |
| A connection `connected` once its socket opened | once the server admitted it, one round trip later |
| A `WSConnection` written by hand | needs `reconnect()`, `state` and `onStateChange` |
| `WSConnectionState.protocol` | `connectionId` |
| A reconnect wait of half to all of the backoff's delay, starting over once the server first answered | a random wait up to all of it, starting over once a connection stayed open 10 s; the page's resume signals reconnect at once unless `ws.reconnectOnResume` is `false` |
| A `4401` ending the connection | credentials asked for anew, and sent once more if they changed |
| A stream's backoff starting over once it delivered something | once it stayed open 10 s |
| A stream's `retry:` field or `Retry-After` waited alone | waited with the backoff's wait on top, never past five minutes |
| A backoff no wait can be drawn from, failing the first reconnect | `subscribeSSE` throws `ConfigurationError` `INVALID_BACKOFF` |
| An in-process subscription telling its status again to a listener added late | its status told as it changes, once |
| A push subscription handed back while its client loads, with `send` | no `send`: a channel alone has it |

### Realtime Errors

| 0.4 | Now |
|---|---|
| `TimeoutError` from `@noverax/courier`, code 4408 | `RealtimeTimeoutError` from `@noverax/courier/realtime`; the root's `TimeoutError` is a call's |
| `AuthError`, `ForbiddenError`, `RateLimitError`, `fromErrorCode` and `isRealtimeError` from `@noverax/courier` | the same names from `@noverax/courier/realtime` |

`RealtimeError` and `ConnectionError` stay at the package root, so a page that catches a realtime error need not load the client for it.

## Protocol Version 2

The client and the server speak protocol version 2, and neither speaks the version before it, so deploy them together — see [Streams & Channels](/docs/advanced/realtime).

| 0.4 | Now |
|---|---|
| A socket let in on its handshake, its first frame read as credentials when it was `auth` | every socket's first frame is `auth` naming version 2, which the server answers with `auth_ok` |
| A page left from 0.4 on an upgraded server | refused with `1002` "Protocol version 2 required: reload the page", which the 0.4 client does not retry |
| A client of this release on a replica of 0.4 | reconnects after a wait, until the rollout has replaced that replica |
| `4429` for a connection given up for a newer one of its key | `4409` |
| `1012` from a stopping server | `1001`, saying when to come back |
| `4008` for a slow consumer | `1013` |
| The client's `ws.heartbeat` and `ws.maxMessageSize` | gone: the server's `heartbeatIntervalMs`, `heartbeatTimeoutMs` and `maxMessageSize` hold, and `auth_ok` tells the client |

A replica of 0.4 does not listen for the commands replicas send each other, so while a rolling upgrade runs, `connections.disconnect()` and `connections.requireAuth()` reach the connections of the replicas already upgraded. Revoke the user's credentials as well: a client that reconnects is then refused by `onConnect`.

## Request Bodies and Uploads

The proxy reads a request body as it arrives, holds it to the limits `createHandler` takes, and answers a body it refuses with the status and the code of why — see [createHandler](/docs/api/api-route#request-bodies) and [File Upload](/docs/advanced/upload).

| 0.4 | Now |
|---|---|
| A body shorter than its `Content-Length` read as if whole, a form answered `400` "Invalid multipart body" | `413` `BODY_INCOMPLETE`, naming both lengths |
| A compressed request body, read as it came | `415` `BODY_ENCODING_UNSUPPORTED` |
| A body read for as long as it took | `408` `BODY_TIMEOUT` after 30 s without a byte (`bodyIdleTimeoutMs`) or 5 minutes in all (`bodyTimeoutMs`) |
| A form of any number of parts | `413` past 1000 parts (`maxUploadParts`), 8 KB of headers a part, or text fields past `maxBodyBytes` together, with `UPLOAD_TOO_MANY_PARTS`, `UPLOAD_PART_HEADERS_TOO_LARGE` or `UPLOAD_FIELDS_TOO_LARGE` |
| A form parsed by the platform's `formData()`, a bare line feed, a header named twice or a part in base64 taken | `400` `BODY_MALFORMED` |
| A JSON body that is not UTF-8, its bytes replaced | `400` `BODY_MALFORMED` |
| An upload kept in memory under Node | its files past `uploadMemoryBytes`, 1 MB, written to `uploadDirectory`, and a disk with no room answered `507` `UPLOAD_STORAGE_FULL`; `uploadMode: "memory"` keeps them in memory |
| Any number of uploads kept at once | they share one room, 64 MB in memory (`totalUploadMemoryBytes`) and 1 GB on disk (`totalUploadDiskBytes`); past it an upload is answered `503` with `Retry-After` and `UPLOAD_CAPACITY_REACHED` |
| A redirect from the upstream followed by an upload or a stream body under Node 22 and 24 | the call fails as a network error: they are sent with `redirect: "error"`, so fetch keeps no copy of them; a `redirect` the caller sets is kept |
| The mock reading a body by itself | the server's own stream and parser, to the same limits |

## Variables

A call's variables are written into its request by one set of rules, in a direct call and on the server behind the proxy alike — see [A file among the variables](/docs/advanced/upload#a-file-among-the-variables).

| 0.4 | Now |
|---|---|
| A direct call's record whose field held a `Blob`, a `File` or bytes, sent as JSON: `{"file":{}}` | sent as a multipart form, each field a part |
| A `Set` or a `Map` in the variables, sent as `{}`; a `BigInt`, a `TypeError` from `JSON.stringify` | `ConfigurationError` `VARIABLE_NOT_ENCODABLE`, naming where it sits, before anything is sent |
| A file in a read's variables, sent in its address as `{}` | `VARIABLE_NOT_ENCODABLE` |
| A read's `FormData`, its fields left out of its address | its text fields sent in the address; a file in it is `VARIABLE_NOT_ENCODABLE` |
| `error.code === "PROXY_VARIABLE_NOT_SERIALIZABLE"` | `error.code === "VARIABLE_NOT_ENCODABLE"`, from a direct call and from a proxy call alike |
| A proxy call's record whose field held a file, refused | sent as a record upload, `multipart/vnd.courier.variables`, which the server restores the record from. A server of an earlier release answers it `415`: deploy the client and the server together |

## Endpoints Addressed with .via()

An endpoint addressed with `.via()` reads or writes as the verb its closure calls does, as one addressed with a verb on the chain does — see [Defining APIs](/docs/core-concepts/defining-apis).

| 0.4 | Now |
|---|---|
| A closure that calls `http.get`, `head`, `options` or `query` — a write until `.reads()` said otherwise | a read: retried, cacheable with `.cache()`, taken by `useQuery`, routed to a page as a read and offered to an agent as one |
| `.via(closure).reads()` for such a closure | `.via(closure)`: `.reads()` changes nothing |
| A GET that changes something — read as it was addressed | `.writes()`: sent once per call, its answer never kept, carried by the proxy as a POST |
| A closure that calls a reading verb on one path and a writing verb on another — a write | no endpoint until `.reads()` or `.writes()` names its kind; a group refuses it with that reason |
| A closure typed `HttpProbe<Variables>` — a write | its type no longer says which verb it calls: leave its return type to be inferred, or name the kind with `.reads()` or `.writes()` |
| A call on which a declared read's closure called `.put()`, `.patch()` or `.del()`, sent and retried as a read | `ConfigurationError` `ENDPOINT_VERB_KIND` before anything is sent; so is a call whose closure calls a verb of the other kind than the one the endpoint was defined with |

## A Page's Imports and a Server's

`@noverax/courier` keeps every name it had. Beside it, `@noverax/courier/client` gives what a page or an app calls an API with, and `@noverax/courier/server` what a server does with one — see [createCaller](/docs/api/create-caller#import). The options a server reads are checked on every way it calls the API with a request, and a page's definitions carry none of the checks: a page and an app check, as they call, only that their session goes nowhere over plain HTTP across the public internet — see [`session`](/docs/api/define#session).

`courier-cli upgrade` moves each import of `@noverax/courier` to the entry of the side that loads its file. A file a page's bundle takes — by its place or its `"use client"`, or as a page's file imports it — takes `@noverax/courier/client`, where that gives every name the import takes. A file only the server loads — a route handler, `*.server.*` or a file in a `.server/` folder, `server/`, middleware, instrumentation, an API route, a module of server functions with `"use server"`, whose code a page that imports it never takes, a file of a server that no page's file imports, or a module only they import — takes `@noverax/courier/server`. Under React Router and Remix a page never takes a `.server` module, and the server never runs a `.client` one, as their builds leave them out.

A server is told by the framework its package lists: Express, Fastify, Hono, NestJS, Koa, hapi, Elysia, h3 or Nitro. h3 and Nitro are built to be the server of a page's framework: beside Nuxt, SolidStart, TanStack Start or Analog each is that framework's own, and beside a page Vite builds whose framework the upgrade does not know — Preact's, Lit's, Svelte's without Kit, or a page of no framework — no file of the package is told a side, and the plan names each import it leaves in the root. Where a server runs beside a page Vite builds, the page is told by where Vite starts it, whatever framework builds it — React, Vue, Preact, Svelte, Lit or none: the module scripts of its `index.html`, or the `root` and `build.rollupOptions.input` its config gives as data — a string, or one `resolve()`, `join()` or `fileURLToPath()` makes of the config's own folder and strings. A file only the page reaches is the page's, one only the server reaches the server's, and one both reach stays in the root. Where Vite has no entry at all — no `index.html` and no input — and the package renders no page, as where Vite is a tool of the server's, the server's rules read the package. Where it lists what a page renders with — React, Vue, Svelte, Solid, Preact, Lit or the like — a page another bundler builds with it, webpack or Parcel say, and a server that renders HTML with it alone look alike to Courier; there, and where Vite's entry is there but Courier cannot read it — an input or a root of another form, a config that spreads another — no file of the package is told a side, and the plan says why. A tool's config — Vite's, Vitest's, a bundler's, a linter's — takes no side, and what it names takes none from it. A package whose server is none of these is read as a page's alone, every file under its `src/` the page's: look over what the plan changes in that server's files.

The upgrade follows your imports through relative paths, tsconfig `paths`, package.json `imports`, the framework's aliases and the workspace's packages — an `imports` key and a package's `exports` by the first condition each side takes, a package without `exports` by its `module` and `main` — and through `import.meta.glob` written with literals — strings, or templates with nothing put in them — as Vite reads it, and `new URL(…, import.meta.url)`. A `/` in a glob, its `base` or an import is read from each folder Vite may take for its root: the folder of an `index.html` it builds from, and the package's own. A query names a file by what Vite loads of it: `?worker` and `?sharedworker` a worker's code, on the side of the file that starts it; `?url` its address, which that side may load it by; `?raw` its text, which nothing runs — and a glob's `query` the same. It reads the frontmatter and the scripts of an Astro file apart, and Expo Router's folder of routes from app.json, or from an `app.config` written as data, which it does not run. It never reads `node_modules`, the folders of version control, or what builds and frameworks write at a package's root — `dist`, `build`, `out`, `coverage`, `.next`, `.nuxt`, `.output`, `.svelte-kit` and the like — where a folder of the same name deeper is read; a folder deeper than 16, one it cannot open, a link out of the workspace and a file over 2 MiB it names in the plan.

Some imports stay in the root, and the plan says why and what to write:
- one with `createCaller`, in a file the server loads or may load too, with the server's file that leads to it: from the root that is the server's caller; give the page and the server a module each;
- a page's import of the server's names, or of the root whole;
- a page's import of [`redact()`](/docs/api/redact), which `@noverax/courier/client` leaves out, so a page takes it from the root;
- one in a package a page loads by its name, whose entry leads to no code the upgrade reads, as a build's output;
- one in a file neither the framework's rules nor the imports tell a side of.

The plan also names what it could not read a side by: a Nuxt config whose `extends` is not data, an Expo `app.config` whose routes are not, and an `import.meta.glob` that takes what is not a literal — a template with something put in it among them — which Vite does not build either.

An `import()` or a `require()` of `@noverax/courier` moves as an import does where the names it takes are in sight — `const { isHTTPError } = await import(…)`, `.then(({ isHTTPError }) => …)`, or a binding used only by its members in the scope that declares it; a page's that takes the root whole is named. A type moves with its import. An import of types alone, which no bundle loads, moves to an entry that gives every type it names, with nothing said; one that writes `type` on each name does so only where your tsconfig drops it, as under `verbatimModuleSyntax` it loads the module and is read as an import of values. An import already on an entry, or of a subpath, is left as it is.

| 0.4 | Now |
|---|---|
| A `session`, a `forward` or a header list beside a session that could not work as written, refused by `defineApi` in every runtime | refused before any call, whatever `NODE_ENV` says, on every way a server calls the API with a request — its sources registered, a handler made with them, the server's caller or a Server Action made, `ensureCsrfToken`, the first call it lends a request's session to; a page's `defineApi` refuses none of it, and a page or an app refuses, as it makes it, a call that would carry its session over plain HTTP across the public internet |
| A change to an API's `session`, `forward` or a header list after a server took the API up, sent by the next call unchecked | held as it was checked: `api.options` gives a frozen copy of each, a change made through it throws a `TypeError`, and a change to the objects given to `defineApi`, which stay yours, reaches no call |
| `.agent()` given what it does not take, refused where the endpoint was written | `AGENT_OPTIONS_INVALID` as a server's sources are registered, a handler or its caller is made with them, and as `courier-mcp` lists its tools, naming where `.agent()` was written |
| `createCaller` from `@noverax/courier` in a page | the same caller, with the server's part beside it; `createCaller` from `@noverax/courier/client` leaves that out of the page |
| `createCaller` from `@noverax/courier` under Vitest with jsdom, or in an Electron renderer with `nodeIntegration` that loads Courier as Node does, cancelling a superseded read and carrying the page's session where no request is being served, as in a page | the server's caller there, whose calls cancel none and carry no page's session: a test of a page's calls, and such a renderer, take `createCaller` from `@noverax/courier/client`. Jest with jsdom takes the `browser` condition, and its root caller is a page's, which does both still, while the caller of `@noverax/courier/server` is refused there as it is made |
| A test in Vitest's or Jest's `node` environment of a page's module that takes `createCaller` from `@noverax/courier` | once `courier-cli upgrade` moves the module to `@noverax/courier/client`, the page's caller under Node, where no `document` is: as the root's caller there before, its calls are not one user's, so it cancels no superseded read, and a call of an API that keeps a session or forwards headers, whose context names a request, is refused with `ConfigurationError` `SERVER_CAPABILITY_MISSING` until something lends it the server's part. In jsdom it cancels a superseded read, as on a page. Run such a test in jsdom, as the page runs, or lend the part in its setup — register the sources with `registerSources` from `@noverax/courier/server` — and test the server's own calls through the server's module |

What Studio writes from an imported specification, and the hash it keeps of one — see [Import an API](/docs/studio/import-api).
