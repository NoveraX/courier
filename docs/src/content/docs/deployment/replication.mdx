This guide shows a complete, production-ready realtime setup with Redis adapters for each supported framework.

<Callout variant="info" title="Prerequisites">
  All examples assume you have created shared adapters as shown in the [Redis Adapters](/docs/deployment/redis) page. The `adapters.ts` file is reused across all frameworks.
</Callout>

## Shared Adapters

Every framework uses the same adapter setup. The server is handed `pubsub`; `history` and `presence` are used by your stream and channel handlers, as the [Redis Adapters](/docs/deployment/redis) page shows:

```ts title="lib/adapters.ts"
import Redis from "ioredis"
import { createRedisPubSub, createRedisStream, createRedisPresence } from "@noverax/courier-redis"

const redisUrl = process.env.REDIS_URL ?? "redis://localhost:6379"

export const pubsub = createRedisPubSub({
  publisher: new Redis(redisUrl),
  subscriber: new Redis(redisUrl),
  prefix: "courier:",
  origin: process.env.HOSTNAME,
})

export const history = createRedisStream({
  redis: new Redis(redisUrl),
  prefix: "courier:stream:",
  maxLen: 5000,
})

export const presence = createRedisPresence({
  redis: new Redis(redisUrl),
  subscriber: new Redis(redisUrl),
  prefix: "courier:presence:",
})

export async function connectAdapters(): Promise<void> {
  await Promise.all([pubsub.connect(), history.connect(), presence.connect()])
}

export async function disconnectAdapters(): Promise<void> {
  await Promise.all([pubsub.disconnect(), history.disconnect(), presence.disconnect()])
}
```

Awaiting `connectAdapters()` at startup checks that Redis is there; it is not what makes the Pub/Sub adapter work. The adapter keeps every subscription it was asked for and makes it once Redis answers, and holds what is published until then within its queue's bounds. A replica that started while Redis was down, or lost it on the way, hears the other replicas once Redis is back, and `connect()` rejecting at its deadline leaves the adapter connecting. See [Redis Adapters](/docs/deployment/redis#pubsub-adapter).

## Standalone Server

The simplest setup — one process handles HTTP, SSE, and WebSocket.

```ts title="server.ts"
import { createCourierServer } from "@noverax/courier-server"
import { sources } from "./api/sources"
import { pubsub, connectAdapters, disconnectAdapters } from "./lib/adapters"

await connectAdapters()

const server = await createCourierServer({
  sources,
  port: Number(process.env.PORT) || 3001,
  host: "0.0.0.0",
  allowedOrigins: [process.env.ALLOWED_ORIGIN!],
  pubsub,

  // SSE
  maxSSEConnections: 10_000,
  sseMaxLifetimeMs: 300_000,
  onSSEConnect: ({ connectionId, request, source, group, method }) => {
    return { userId: extractUser(request) }
  },
  onSSEDisconnect: ({ meta, reason, eventCount, duration }) => {
    console.log(`SSE closed: user=${meta.userId} reason=${reason} events=${eventCount}`)
  },

  // WebSocket
  heartbeatIntervalMs: 25_000,
  onConnect: ({ connectionId, request }) => {
    const userId = extractUser(request)
    if (!userId) throw new Error("Unauthorized")
    return { userId }
  },
  onDisconnect: ({ meta, code }) => {
    console.log("WS closed", { meta, code })
  },

  onReady: (url) => console.log(`Courier ready at ${url}`),
})

process.on("SIGTERM", async () => {
  await server.stop()
  await disconnectAdapters()
})
```

## Next.js

Next.js App Router supports SSE natively via `sseRoute()`. WebSocket requires a separate Courier server process.

### SSE Route

```ts title="app/api/sse/route.ts"
import { sseRoute } from "@noverax/courier-next"

export const { GET } = sseRoute({
  maxSSEConnections: 5000,
  sseMaxLifetimeMs: 300_000,
  sseHeaders: {
    "Access-Control-Allow-Origin": process.env.NEXT_PUBLIC_APP_URL!,
  },
  onSSEConnect: ({ connectionId, request }) => {
    return { userId: extractUser(request) }

```

import { apiRoute } from "@noverax/courier-next"

export const { GET, POST } = apiRoute()

## Express

```ts title="server.ts"
import http from "node:http"
import express from "express"
import { registerSources } from "@noverax/courier"
import { courierHandler, courierSSEHandler, courierWSAttach } from "@noverax/courier-express"
import { sources } from "./api/sources"
import { pubsub, connectAdapters, disconnectAdapters } from "./lib/adapters"

registerSources(sources)
await connectAdapters()

const app = express()
const server = http.createServer(app)

// HTTP proxy
const proxy = courierHandler()
app.all("/api/request", proxy)

// SSE streaming — do NOT apply compression middleware to this route
const sse = courierSSEHandler({
  maxSSEConnections: 10_000,
  sseMaxLifetimeMs: 300_000,
  onSSEConnect: ({ connectionId, request }) => {
    return { userId: extractUser(request) }
  },
  onSSEDisconnect: ({ meta, reason, eventCount }) => {
    console.log(`SSE closed: ${meta.userId}, ${reason}, ${eventCount} events`)
  },
})
app.get("/api/sse", sse)

// WebSocket — answers upgrades on `path` only; set the client's proxyPath.ws to match
const cleanupWS = courierWSAttach(server, {
  path: "/api/ws",
  pubsub,
  heartbeatIntervalMs: 25_000,
  allowedOrigins: [process.env.ALLOWED_ORIGIN!],
  maxSubscriptionsPerConnection: 100,
  maxMessageSize: 65_536,
  onConnect: ({ request }) => {
    const userId = extractUser(request)
    if (!userId) throw new Error("Unauthorized")
    return { userId }
  },
  onDisconnect: ({ meta, code }) => {
    console.log("WS closed", { meta, code })
  },
})

// Health checks
app.get("/health", (req, res) => res.json({ status: "ok" }))
app.get("/readyz", (req, res) => {
  res.status(shuttingDown ? 503 : 200).send(shuttingDown ? "draining" : "ready")
})

let shuttingDown = false
server.listen(Number(process.env.PORT) || 3001, "0.0.0.0")

process.on("SIGTERM", async () => {
  shuttingDown = true
  // server.close() waits for open streams and sockets, so drain them first:
  // SSE clients get a `courier:shutdown` notice; cleanupWS() refuses new upgrades,
  // closes each socket with 1012 and settles within 5 seconds, whatever Redis does.
  await Promise.all([proxy.shutdownSSE(), sse.shutdownSSE(), cleanupWS()])
  server.close()
  await disconnectAdapters()
})
```

<Callout variant="warning" title="SSE and compression">
  Do **not** apply compression middleware (like `compression()`) to the SSE route. Compression buffers the response, breaking the streaming behavior.
</Callout>

## Fastify

```ts title="server.ts"
import Fastify from "fastify"
import fastifyWebsocket from "@fastify/websocket"
import { wsFrameLimit } from "@noverax/courier/node"
import { registerSources } from "@noverax/courier"
import { courierPlugin, courierSSEHandler, courierWSHandler } from "@noverax/courier-fastify"
import { sources } from "./api/sources"
import { pubsub, connectAdapters, disconnectAdapters } from "./lib/adapters"

registerSources(sources)
await connectAdapters()

const fastify = Fastify({ logger: true })

// WebSocket plugin (must register before WS routes). Its ws server reads
// frames up to maxPayload before Courier sees them — 100 MiB by default —
// so bound it as Courier's own servers do (wsFrameLimit from "@noverax/courier/node")
await fastify.register(fastifyWebsocket, { options: { maxPayload: wsFrameLimit() } })

// HTTP proxy
await fastify.register(courierPlugin, { prefix: "/api/request" })

// SSE streaming — the plugin drains its own streams on close; this route
// drains in preClose, or fastify.close() waits for its streams to end
const sse = courierSSEHandler({
  maxSSEConnections: 10_000,
  sseMaxLifetimeMs: 300_000,
  onSSEConnect: ({ connectionId, request }) => {
    return { userId: extractUser(request) }
  },
  onSSEDisconnect: ({ meta, reason, eventCount }) => {
    console.log(`SSE closed: ${meta.userId}, ${reason}, ${eventCount} events`)
  },
})
fastify.get("/api/sse", sse)
fastify.addHook("preClose", () => sse.shutdownSSE())

// WebSocket
fastify.get("/ws", { websocket: true }, courierWSHandler({
  pubsub,
  heartbeatIntervalMs: 25_000,
  allowedOrigins: [process.env.ALLOWED_ORIGIN!],
  maxSubscriptionsPerConnection: 100,
  onConnect: ({ request }) => {
    const userId = extractUser(request)
    if (!userId) throw new Error("Unauthorized")
    return { userId }
  },
  onDisconnect: ({ meta, code }) => {
    console.log("WS closed", { meta, code })
  },
}))

// Health checks
fastify.get("/health", async () => ({ status: "ok" }))
fastify.get("/readyz", async (req, reply) => {
  reply.status(shuttingDown ? 503 : 200).send(shuttingDown ? "draining" : "ready")
})

let shuttingDown = false
await fastify.listen({ port: Number(process.env.PORT) || 3001, host: "0.0.0.0" })

process.on("SIGTERM", async () => {
  shuttingDown = true
  await fastify.close()
  await disconnectAdapters()
})
```

## Hono

Hono is runtime-agnostic — this example uses Node.js with `@hono/node-server`, which carries its own WebSocket upgrade helper.

```ts title="server.ts"
import { Hono } from "hono"
import { serve, upgradeWebSocket } from "@hono/node-server"
import { WebSocketServer } from "ws"
import { registerSources } from "@noverax/courier"
import { courierHandler, courierSSEHandler, courierWSHandler } from "@noverax/courier-hono"
import { sources } from "./api/sources"
import { pubsub, connectAdapters, disconnectAdapters } from "./lib/adapters"

registerSources(sources)
await connectAdapters()

const app = new Hono()
const wss = new WebSocketServer({ noServer: true })

// HTTP proxy
app.all("/api/request", courierHandler())

// SSE streaming
app.get("/api/sse", courierSSEHandler({
  maxSSEConnections: 10_000,
  sseMaxLifetimeMs: 300_000,
  onSSEConnect: ({ connectionId, request }) => {
    return { userId: extractUser(request) }
  },
}))

// WebSocket
const ws = courierWSHandler({
  pubsub,
  heartbeatIntervalMs: 25_000,
  allowedOrigins: [process.env.ALLOWED_ORIGIN!],
  onConnect: ({ request }) => {
    const userId = extractUser(request)
    if (!userId) throw new Error("Unauthorized")
    return { userId }
  },
  onDisconnect: ({ meta, code }) => {
    console.log("WS closed", { meta, code })
  },
})
app.get("/ws", upgradeWebSocket((c) => ws(c)))

// Health checks
app.get("/health", (c) => c.json({ status: "ok" }))

const server = serve({
  fetch: app.fetch,
  port: Number(process.env.PORT) || 3001,
  hostname: "0.0.0.0",
  websocket: { server: wss },
})

process.on("SIGTERM", async () => {
  server.close()
  await disconnectAdapters()
})
```

<Callout variant="tip" title="Other runtimes">
  For Bun, Deno, or Cloudflare Workers, replace `@hono/node-server` with the runtime-specific WebSocket API. See the [Cloudflare](/docs/deployment/cloudflare) page for Workers setup.
</Callout>

## NestJS

```ts title="main.ts"
import { NestFactory } from "@nestjs/core"
import { registerSources } from "@noverax/courier"
import { courierWSAttach } from "@noverax/courier-nestjs"
import { AppModule } from "./app.module"
import { sources } from "./api/sources"
import { pubsub, connectAdapters, disconnectAdapters } from "./lib/adapters"

async function bootstrap(): Promise<void> {
  registerSources(sources)
  await connectAdapters()

  const app = await NestFactory.create(AppModule)

  // WebSocket — answers upgrades on `path` only; set the client's proxyPath.ws to match
  const cleanupWS = courierWSAttach(app.getHttpServer(), {
    path: "/api/ws",
    pubsub,
    heartbeatIntervalMs: 25_000,
    allowedOrigins: [process.env.ALLOWED_ORIGIN!],
    onConnect: ({ request }) => {
      const userId = extractUser(request)
      if (!userId) throw new Error("Unauthorized")
      return { userId }
    },
    onDisconnect: ({ meta, code }) => {
      console.log("WS closed", { meta, code })
    },
  })

  await app.listen(Number(process.env.PORT) || 3001, "0.0.0.0")

  process.on("SIGTERM", async () => {
    // AppModule drains its SSE streams in beforeApplicationShutdown
    await cleanupWS()
    await app.close()
    await disconnectAdapters()
  })
}

bootstrap()
```

```ts title="app.module.ts"
import {
  type BeforeApplicationShutdown,
  Module,
  type NestModule,
  type MiddlewareConsumer,
} from "@nestjs/common"
import { courierMiddleware, courierSSEMiddleware } from "@noverax/courier-nestjs"

const proxy = courierMiddleware()
const sse = courierSSEMiddleware({
  maxSSEConnections: 10_000,
  sseMaxLifetimeMs: 300_000,
  onSSEConnect: ({ connectionId, request }) => {
    return { userId: extractUser(request) }
  },
  onSSEDisconnect: ({ meta, reason, eventCount }) => {
    console.log(`SSE closed: ${meta.userId}, ${reason}, ${eventCount} events`)
  },
})

@Module({})
export class AppModule implements NestModule, BeforeApplicationShutdown {
  configure(consumer: MiddlewareConsumer): void {
    consumer.apply(proxy).forRoutes("/api/request")
    consumer.apply(sse).forRoutes("/api/sse")
  }

  // app.close() waits for open streams, so they are drained before it does
  async beforeApplicationShutdown(): Promise<void> {
    await Promise.all([proxy.shutdownSSE(), sse.shutdownSSE()])
  }
}
```

## A User's Connections, on Every Replica

`connections.disconnect()` and `connections.requireAuth()` reach the connections a selector names on every replica that shares the pub/sub adapter, so signing a user out, or banning one, closes their connections wherever the load balancer sent them:

```ts title="sign-out.ts"
import type { ConnectionRegistry } from "@noverax/courier"

export async function signOutEverywhere(connections: ConnectionRegistry, userId: string) {
  // Each connection whose onConnect returned this userId, on every replica
  await connections.disconnect({ meta: { userId } }, { code: 4001, reason: "Signed out" })
}

export async function askForFreshTokens(connections: ConnectionRegistry, userId: string) {
  // Each of them sends its credentials again within 30 seconds, or is closed with 4401
  await connections.requireAuth({ meta: { userId } }, { timeoutMs: 30_000 })
}
```

A selector is a connection id, `{ id }` with as many as 1000 of them, or `{ meta }` comparing up to 16 fields of what `onConnect` returned, each to a string, a number or a boolean. One the handler cannot use — no id, a field compared to an object — rejects with a `TypeError` before anything is closed, and so does a code no socket can send. The call resolves once this replica's connections are closed and the command for the others has gone to the adapter; it is not sent at all when every id it names is this replica's. A replica Redis cannot reach at that moment misses the command, so revoke the user's credentials as well: a client that reconnects is then refused by `onConnect`. `count`, `get`, `list()` and `send()` stay with the replica that holds the connections.

### Signing the commands

Whoever can publish on the adapter's channels can send the replicas a command — on a Redis anything else reaches, close any connection. Give every replica the same secret of 32 bytes or more, and each command is signed with HMAC-SHA-256; one that is not signed, or not with the secret, is refused, and so is one sent again or more than a minute ago, each on one line of the server's log:

```ts title="adapters.ts"
const ws = createWSHandler({
  pubsub,
  cluster: { secret: process.env.COURIER_CLUSTER_SECRET }, // openssl rand -hex 32
})
```

A shorter secret throws `CLUSTER_SECRET_INVALID` when the handler is made. Keep the secret out of the repository, as any credential, and keep publishing on the prefix's channels to your application with Redis ACLs as well.

### Coming from 0.4

| 0.4 | Now |
|-----|-----|
| `disconnect(id, code, reason)` | `await disconnect(id, { code, reason })` |
| `disconnectByMeta((meta) => meta.userId === id, code, reason)` | `await disconnect({ meta: { userId: id } }, { code, reason })` |
| `getByMeta(predicate)` | `list({ meta: { … } })`, or `list().filter(…)` for any other test |
| `sendAuthRequired(connections, id, ms)` | `await connections.requireAuth(id, { timeoutMs: ms })` |

A replica of 0.4 does not listen for commands, so while a rolling upgrade from it runs, a command reaches the replicas already upgraded. A replica that gets a command of a newer version than its own skips it, saying so in its log.

## Sticky Sessions

Multi-replica deployments **require sticky sessions** for both SSE and WebSocket. The load balancer must route all requests from the same client to the same replica for the duration of a connection.

Configure this at the infrastructure level:

- **nginx**: `upstream` with `ip_hash` or cookie-based affinity
- **Traefik**: `sticky.cookie` in service definition
- **K8s Ingress**: `nginx.ingress.kubernetes.io/affinity: cookie`
- **Cloudflare**: Enabled by default for WebSocket

See the [Docker](/docs/deployment/docker) and [Kubernetes](/docs/deployment/kubernetes) pages for specific configuration.
