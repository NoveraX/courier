Building a web app that talks to a REST API sounds simple — until you need type safety, a proxy layer, cookie forwarding, error handling, upload progress, middleware, validation, and framework integration. Each of these adds boilerplate, and without a unified approach, your API logic scatters across dozens of files.

Courier solves this by giving you a single, typed API definition that works across any framework — its types inferred, never generated.

## The Problem

A typical frontend + REST API setup requires you to:

1. Write `fetch` calls with manual URL construction, headers, and error handling
2. Cast response types manually with no runtime guarantee
3. Create separate API routes for every endpoint you want to proxy
4. Duplicate type annotations between your fetch logic and your components
5. Wire up React Query (or Vue composables, Svelte stores) with custom keys and fetch functions per endpoint

This leads to fragile, repetitive code:

```typescript title="Without Courier"
// Manual fetch — no type safety, lots of boilerplate
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/users/${id}`, {
  headers: { Authorization: `Bearer ${token}` },
})
if (!res.ok) throw new Error("Failed to fetch user")
const user = (await res.json()) as User // manual cast, no guarantee

// Need a proxy? Write a route handler for every endpoint...
```

With Courier, the same functionality is type-safe and zero-boilerplate:

```typescript title="With Courier"
// Type-safe, fully inferred
const user = await caller.users.getById({ id: "5" })
//    ^? User — inferred from .response<User>()

// Proxy? One line in your server:
export const { GET, POST } = apiRoute() // or courierHandler()
// Done. Every endpoint works through this single route.
```

## Define Once, Use Everywhere

You define your API structure **once** using `courier`, `defineGroup`, and `defineApi`. Each endpoint declares its response and variables types. From that single definition, Courier gives you:

- **Direct mode** — server calls via `createCaller(api)`
- **Proxy mode** — browser calls via `createProxyCaller(apiRoutes)`, the endpoints you marked `.expose()`
- **React Query** — hooks via `createProxyQueryCaller(apiRoutes)`
- **Server Actions** — server-action calls via `createAction(sources, "api")`

All share the same types and autocomplete:

```typescript title="One definition, multiple modes"
// Define once
const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: endpoint.get("").response<User[]>(),
    getById: endpoint.get(":id").variables<{ id: string }>().response<User>(),
    create: endpoint.post("").variables<CreateUserVars>().response<User>(),
  },
})

// Direct — server-side
const onServer = await caller.users.getById({ id: "5" })

// Proxy — client-side
const inBrowser = await proxyCaller.users.getById({ id: "5" })

// React Query — same types again
const { data } = q.users.useQuery("getById", { variables: { id: "5" } })
```

<Callout variant="tip" title="Types inferred, never generated">
Unlike GraphQL codegen or a client generated from an OpenAPI document, Courier takes its types from plain TypeScript definitions: no type files to regenerate, no step to run before you compile. Rename a method and TypeScript catches every broken call site instantly. Proxy mode keeps one file written for you — `courier.routes.ts`, the list of what a page may call — which a review reads and CI checks; see [Exposing Endpoints](/docs/proxy-mode/expose).
</Callout>

## One Proxy Route for Everything

Without Courier, proxying requests means creating a route for every backend endpoint. With Courier, a single handler covers all endpoints. It automatically:

- Validates the request origin (CSRF protection)
- Forwards the headers and the cookies you name, and nothing else
- Routes to the correct source, group, and method
- Handles errors with proper HTTP status codes
- Supports file uploads and multipart encoding

## React Query Without the Boilerplate

```typescript title="React Query comparison"
// Traditional — manual setup per endpoint
const { data } = useQuery({
  queryKey: ["users", id],
  queryFn: async () => {
    const res = await fetch(`/api/users/${id}`)
    if (!res.ok) throw new Error("fetch failed")
    return res.json() as Promise<User>
  },
})

// Courier — one line, fully typed
const { data: user } = q.users.useQuery("getById", { variables: { id } })
//            ^? User
```

## Who is it for?

Courier is designed for teams and projects that:

- Use any modern framework (Next.js, Nuxt, React, Vue, Hono, Express, etc.)
- Have a separate REST backend (Express, FastAPI, Rails, Go, Laravel — anything)
- Want type safety without adopting tRPC or GraphQL
- Need both client-side and server-side data fetching
- Value DX — autocomplete, compile-time errors, minimal boilerplate

<Callout variant="info" title="Works with any REST backend">
Courier does not require a specific backend framework. It works with any HTTP API that returns JSON. Your backend needs zero Courier-specific setup.
</Callout>
