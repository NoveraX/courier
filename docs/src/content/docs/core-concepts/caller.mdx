## Overview

Nexus provides two ways to call your API endpoints. Both share the same `TypedClient` interface and the same type inference:

| Factory | Mode | Use Case |
|---------|------|----------|
| `createCaller(api)` | Direct | Server-side, Node.js, Bun, Deno, scripts |
| `createProxyCaller<typeof api>()` | Proxy | Browser → your server → backend |

## createCaller (Direct Mode) <ModeBadge mode="direct" />

Calls your backend directly. Works in any JavaScript runtime with `fetch`.

```ts title="lib/caller.ts"
import { createCaller } from "@noverax/nexus"
import { api } from "@/api/sources"

export const caller = createCaller(api)
```

```ts
// Works anywhere: Node.js, Bun, Deno, Server Components, scripts
const users = await caller.users.getAll()
//    ^? User[]

const user = await caller.users.getById({ id: "1" })
//    ^? User
```

<Callout variant="info" title="When to use direct mode">
Use direct mode for server-side code where you have access to the `api` object: Server Components, Server Actions, API routes, CLI scripts, cron jobs.
</Callout>

## createProxyCaller (Proxy Mode) <ModeBadge mode="proxy" />

Sends requests through your server's proxy route. The browser never sees your backend URL.

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/nexus"
import type { api } from "@/api/sources"

export const caller = createProxyCaller<typeof api>({
  proxyUrl: "/api/request",   // default
  timeout: 10000,
  credentials: "include",     // forward cookies
  headers: { "X-Custom": "value" },
  onError: (error) => console.error(error),
  onSuccess: (data) => console.log(data),
})
```

```ts
// Browser sends POST /api/request → your server → backend
const users = await caller.users.getAll()
```

<Callout variant="tip" title="Type-only import">
Notice that proxy mode imports `type { api }` — the actual `api` object stays on the server. Only the type information is used for inference.
</Callout>

### ProxyCallerDefaults

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `proxyUrl` | `string` | `"/api/request"` | Proxy endpoint URL |
| `timeout` | `number` | — | Request timeout in ms |
| `credentials` | `RequestCredentials` | `"include"` | Cookie forwarding mode |
| `headers` | `Record<string, string>` | — | Default headers |
| `onError` | `(error: HTTPError) => void` | — | Global error callback |
| `onSuccess` | `(data: unknown) => void` | — | Global success callback |

## The Dot-Notation Interface

Both factories return a typed client with dot-notation access:

```ts
const caller = createCaller(api)

// Access endpoints via group.method notation
const users = await caller.users.getAll()
const user = await caller.users.getById({ id: "1" })
```

### Call Options

Pass runtime options as the second argument after variables:

```ts
// Stream mode — returns raw Response
const response = await caller.events.stream.stream()

// GET proxy — encodes as query params instead of POST body
const users = await caller.users.getAll({ page: 1 }, { method: "GET" })

// Upload progress tracking
await caller.files.upload(formData, {
  onUploadProgress: ({ percent }) => console.log(`${Math.round(percent * 100)}%`),
})

// Abort signal
const controller = new AbortController()
await caller.users.getAll(undefined, { signal: controller.signal })
```

## Using Both Modes Together

Most apps use both modes — proxy for the browser, direct for the server:

```ts title="lib/caller.ts"
import { createCaller, createProxyCaller } from "@noverax/nexus"
import { api } from "@/api/sources"

// Server-side (RSC, Server Actions, API routes)
export const serverCaller = createCaller(api)

// Client-side (React components)
export const clientCaller = createProxyCaller<typeof api>()
```
