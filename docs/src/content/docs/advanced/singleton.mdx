## The problem

Without the singleton pattern, you need to pass the API type as a generic parameter to every factory function. This is repetitive and creates multiple places to update when your API changes:

```ts title="lib/caller.ts"
import { createProxyCaller, createCaller } from "@noverax/courier"
import { createProxyQueryCaller } from "@noverax/courier-react"
import { api } from "@/api"

// You have to pass the type everywhere:
const caller = createProxyCaller<typeof api>("api")
const directCaller = createCaller(api)
const q = createProxyQueryCaller<typeof api>("api")
```

## The solution

TypeScript module augmentation lets you declare your API type once, and every Courier factory function infers it automatically. No generic parameters needed.

## Step-by-step setup

### Step 1: Define your API with the functional API

Create your groups and API definition using `defineGroup`, `endpoint`, and `defineApi`:

```ts title="api/users.ts"
import { defineGroup, endpoint } from "@noverax/courier/define"

type User = { id: number; name: string; email: string }

export const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: endpoint<User[]>()((http) => http.get()),
    getById: endpoint<User, { id: number }>()((http, vars) => http.get(":id", vars)),
    create: endpoint<User, { name: string; email: string }>()((http, vars) => http.post("", vars)),
  },
})
```

```ts title="api/index.ts"
import { defineApi } from "@noverax/courier/define"
import { users } from "./users"

export const api = defineApi({
  baseURL: process.env.API_URL ?? "http://localhost:4000",
  groups: { users },
})
```

### Step 2: Augment the module

Create a `.d.ts` file that extends the Courier `DefaultApi` interface:

```ts title="types/courier.d.ts"
import type { api } from "@/api"

declare module "@noverax/courier/define" {
  interface DefaultApi {
    api: typeof api
  }
}
```

<Callout variant="tip" title="File location">
You can put this declaration anywhere TypeScript can see it — a dedicated `types/` directory, alongside your API definitions, or in a global `declarations.d.ts`. Just make sure it's included in your `tsconfig.json`.
</Callout>

### Step 3: Use without generics

Now all factory functions infer your API type from the augmented interface. TypeScript provides full autocomplete for group names, method names, and variable types:

```ts title="lib/caller.ts"
import { createProxyCaller, createCaller } from "@noverax/courier"
import { createProxyQueryCaller } from "@noverax/courier-react"
import { api } from "@/api"

// No generic parameter needed — TypeScript infers from module augmentation
const caller = createProxyCaller("api")
const directCaller = createCaller(api)
const q = createProxyQueryCaller("api")

// Full autocomplete: group names, method names, variable types
q.users.useQuery("getById", { variables: { id: 1 } })
//       ^-- autocomplete     ^-- autocomplete  ^-- typed
```

## Using with React Query

The singleton pattern is especially useful with `createProxyQueryCaller`, where you access hooks throughout your app. Every call site gets full type inference without importing or passing types:

```tsx title="components/user-list.tsx"
"use client"

import { q } from "@/lib/caller"

export function UserList() {
  // TypeScript knows "users" is a valid group,
  // "getAll" is a valid method,
  // and data is User[]
  const { data } = q.users.useQuery("getAll")

  const { mutate } = q.users.useMutation("create", {
    onSuccess: (user) => {
      // user is typed as User — no generic needed
      console.log(user.name)
    },
  })

  return (
    <div>
      {data?.map((user) => <p key={user.id}>{user.name}</p>)}
      <button onClick={() => mutate({ name: "Jane", email: "jane@test.com" })}>
        Add User
      </button>
    </div>
  )
}
```

## Multiple sources

If your app connects to multiple backends, define multiple APIs and augment the interface for each:

```ts title="types/courier.d.ts"
import type { mainApi, paymentApi } from "@/api"

declare module "@noverax/courier/define" {
  interface DefaultApi {
    mainApi: typeof mainApi
    paymentApi: typeof paymentApi
  }
}
```

```ts
// Create separate query callers for each source:
const mainQ = createProxyQueryCaller("mainApi")
const paymentQ = createProxyQueryCaller("paymentApi")

mainQ.users.useQuery("getAll")        // ← knows mainApi groups
paymentQ.products.useQuery("list")    // ← knows paymentApi groups
```

<Callout variant="info" title="Single source of truth">
The `DefaultApi` interface is the single source of truth for your API types. When you add a new group or method, update the API definition and every `q.{group}.useQuery()` / `caller.{group}.{method}()` call gets autocomplete for the new endpoints immediately.
</Callout>
