## The problem

Without the singleton pattern, you need to pass the `Sources` generic type parameter to every factory function. This is repetitive and creates multiple places to update when sources change:

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/nexus"
import { createCaller } from "@noverax/nexus"
import { createQueryCaller } from "@noverax/nexus-query"
import type { Sources } from "@/api"

// You have to pass the Sources generic everywhere:
const call = createProxyCaller<Sources>()
const directCall = createCaller<Sources>(sources)
const { useQuery, useMutation } = createQueryCaller<Sources>()
```

## The solution

TypeScript module augmentation lets you declare your sources once, and every Nexus factory function infers them automatically. No generic parameters needed.

## Step-by-step setup

### Step 1: Define your API with the functional API

Create your groups and sources using `defineGroup`, `endpoint`, and `defineApi`. Export the `sources` object so the type declaration can reference it:

```ts title="api/users.ts"
import { defineGroup, endpoint } from "@noverax/nexus/define"

type User = { id: number; name: string; email: string }

export const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: endpoint<User[]>()((http) => http.get()),
    getById: endpoint<User, { id: number }>()((http, vars) => http.get(":id", vars)),
    create: endpoint<User, { name: string; email: string }>()((http, vars) => http.post("", vars)),
  },
})
```

```ts title="api/index.ts"
import { defineApi } from "@noverax/nexus/define"
import { users } from "./users"

const groups = { users }

const api = defineApi({
  baseURL: process.env.API_URL ?? "http://localhost:4000",
  groups,
})

export const sources = { api }
```

### Step 2: Augment the module

Create a `.d.ts` file that extends the Nexus `Sources` interface. Each key in the interface must match a key in your `sources` object:

```ts title="types/nexus.d.ts"
import type { sources } from "@/api"

declare module "@noverax/nexus/define" {
  interface Sources {
    api: (typeof sources)["api"]
  }
}
```

<Callout variant="tip" title="File location">
You can put this declaration anywhere TypeScript can see it — a dedicated `types/` directory, alongside your source definitions, or in a global `declarations.d.ts`. Just make sure it's included in your `tsconfig.json`.
</Callout>

### Step 3: Use without generics

Now all factory functions infer your sources from the augmented interface. TypeScript provides full autocomplete for source names, endpoint keys, and variable types:

```ts title="lib/caller.ts"
import { createProxyCaller, createCaller } from "@noverax/nexus"
import { createQueryCaller } from "@noverax/nexus-query"
import { sources } from "@/api"

// No generic parameter needed — TypeScript infers from module augmentation
const call = createProxyCaller()
const directCall = createCaller(sources)
const { useQuery, useMutation, caller } = createQueryCaller()

// Full autocomplete: source names, group:method endpoints, variable types
useQuery("api", "users:getById", { variables: { id: 1 } })
//        ^-- autocomplete       ^-- autocomplete      ^-- typed
```

## Using with React Query

The singleton pattern is especially useful with `createQueryCaller`, where you call `useQuery` and `useMutation` throughout your app. Every call site gets full type inference without importing or passing types:

```tsx title="components/user-list.tsx"
"use client"

import { useQuery, useMutation } from "@/lib/caller"

export function UserList() {
  // TypeScript knows "api" is a valid source,
  // "users:getAll" is a valid endpoint,
  // and data is User[]
  const { data } = useQuery("api", "users:getAll")

  const { mutate } = useMutation("api", "users:create", {
    onSuccess: (user) => {
      // user is typed as User — no generic needed
      console.log(user.name)
    },
  })

  return (
    <div>
      {data?.map((user) => <p key={user.id}>{user.name}</p>)}
      <button onClick={() => mutate({ name: "Jane", email: "jane@test.com" })}>
        Add User
      </button>
    </div>
  )
}
```

## Multiple sources

If your app connects to multiple backends, add each source to the augmented interface. TypeScript enforces correct endpoint names for each source:

```ts title="types/nexus.d.ts"
import type { sources } from "@/api"

declare module "@noverax/nexus/define" {
  interface Sources {
    mainApi: (typeof sources)["mainApi"]
    paymentApi: (typeof sources)["paymentApi"]
  }
}
```

```ts
// Now both sources are available without generics:
useQuery("mainApi", "users:getAll")       // ← knows mainApi groups
useQuery("paymentApi", "products:list")   // ← knows paymentApi groups
```

<Callout variant="info" title="Single source of truth">
The `Sources` interface is the single source of truth for your API types. When you add a new source or group, update the augmentation and every `useQuery` / `call` call in your app gets autocomplete for the new endpoints immediately.
</Callout>
