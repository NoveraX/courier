export const metadata = { title: "Nuxt", description: "Nuxt integration with courierHandler for server routes, createProxyCaller for client-side, and createCaller for server-side data fetching.", mode: "both" }

Courier works with Nuxt through the `@noverax/courier-nuxt` adapter. Use `courierHandler` for the server proxy route, `createProxyCaller` for client-side requests, and `createCaller` for server-side data fetching.

## Installation

```bash
npm install @noverax/courier @noverax/courier-nuxt
```

## Define your API sources

Create a shared API definition:

```ts title="lib/sources.ts"
import { defineApi, defineGroup, endpoint } from "@noverax/courier/define"

type Post = { id: number; title: string; body: string }
type PostList = { data: Post[]; total: number }

const posts = defineGroup({
  prefix: "posts",
  endpoints: {
    getAll: endpoint<PostList, { page?: number }>()(
      ({ get }) => get()
    ),
    getById: endpoint<Post, { id: number }>()(
      ({ get }) => get(":id")
    ),
    create: endpoint<Post, { title: string; body: string }>()(
      ({ post }) => post()
    ),
    remove: endpoint<null, { id: number }>()(
      ({ del }) => del(":id")
    ),
  },
})

export const api = defineApi({
  baseURL: process.env.API_URL ?? "http://localhost:4000",
  groups: { posts },
})

export const sources = { myApi: api }
```

## Step 1: Server route

Create a Nuxt server route that proxies client requests to your backend:

```ts title="server/plugins/courier.ts"
import { registerSources } from "@noverax/courier"
import { sources } from "~/lib/sources"

export default defineNitroPlugin(() => {
  registerSources(sources)
})
```

```ts title="server/api/request.post.ts"
import { courierHandler } from "@noverax/courier-nuxt"

export default courierHandler()
```

The `server/plugins/courier.ts` Nitro plugin runs once at server start, populating the in-process registry that `courierHandler()` reads at request time. The route then proxies incoming `POST /api/request` requests that Courier clients use as the proxy target.

## Step 2: Client-side composable

Create a composable using `createProxyCaller` for client-side requests:

```ts title="composables/useCaller.ts"
import { createProxyCaller } from "@noverax/courier"
import type { api } from "~/lib/sources"

export const caller = createProxyCaller<typeof api>({
  proxyPath: { http: "/api/request" },
})
```

Use it in your pages and components:

```vue title="pages/posts.vue"
<script setup lang="ts">
import { caller } from "~/composables/useCaller"

const { data: posts, status } = useAsyncData("posts", () =>
  caller.posts.getAll({ page: 1 })
)
</script>

<template>
  <div>
    <p v-if="status === 'pending'">Loading...</p>
    <template v-else-if="posts">
      <h1>Posts ({{ posts.total }})</h1>
      <ul>
        <li v-for="post in posts.data" :key="post.id">
          {{ post.title }}
        </li>
      </ul>
    </template>
  </div>
</template>
```

## Step 3: Server-side data fetching

For server-side data fetching in event handlers, use `createCaller` directly:

```ts title="lib/server-caller.ts"
import { createCaller } from "@noverax/courier"
import { api } from "~/lib/sources"

export const caller = createCaller(api)
```

Use it in Nuxt server routes or event handlers:

```ts title="server/api/dashboard.get.ts"
import { caller } from "~/lib/server-caller"

export default defineEventHandler(async () => {
  const posts = await caller.posts.getAll({ page: 1 })

  return {
    totalPosts: posts.total,
    latestPosts: posts.data.slice(0, 5),
  }
})
```

## Using with useFetch

You can also combine the server caller with `useFetch` for SSR data that hydrates on the client:

```vue title="pages/posts/[id].vue"
<script setup lang="ts">
const route = useRoute()

const { data: post } = useFetch(`/api/posts/${route.params.id}`)
</script>

<template>
  <article v-if="post">
    <h1>{{ post.title }}</h1>
    <p>{{ post.body }}</p>
  </article>
</template>
```

```ts title="server/api/posts/[id].get.ts"
import { caller } from "~/lib/server-caller"

export default defineEventHandler(async (event) => {
  const id = Number(getRouterParam(event, "id"))

  return await caller.posts.getById({ id })
})
```

## Mutations

Handle mutations by calling the proxy caller from client-side event handlers:

```vue title="pages/posts/create.vue"
<script setup lang="ts">
import { caller } from "~/composables/useCaller"

const title = ref("")
const body = ref("")
const isSubmitting = ref(false)

async function handleSubmit() {
  isSubmitting.value = true
  try {
    const post = await caller.posts.create({
      title: title.value,
      body: body.value,
    })
    navigateTo(`/posts/${post.id}`)
  } finally {
    isSubmitting.value = false
  }
}
</script>

<template>
  <form @submit.prevent="handleSubmit">
    <input v-model="title" placeholder="Title" required />
    <textarea v-model="body" placeholder="Body" required />
    <button type="submit" :disabled="isSubmitting">
      {{ isSubmitting ? "Creating..." : "Create Post" }}
    </button>
  </form>
</template>
```

<Callout variant="tip" title="@tanstack/vue-query">
For advanced caching and mutation management, consider using `@tanstack/vue-query` alongside `createProxyCaller`. Courier proxy callers return standard promises, so they work seamlessly with any data-fetching library.
</Callout>

## Realtime (SSE & WebSocket)

The Nuxt adapter currently exposes **HTTP only**. There is no `courierSSEHandler` or `courierWSAttach` export, on purpose: Nitro/H3's WebSocket layer (`crossws`) is still flagged experimental and its production behavior across deployment targets (`node-server`, `bun`, `cloudflare`, `vercel-edge`) is not yet stable enough to ship as a first-class adapter API. SSE through Nitro works in Node, but pinning the public API to it before WS lands would create a split contract we'd then have to deprecate.

**Once Nitro/H3 ship a production-grade WebSocket API**, `courierSSEHandler` and `courierWSAttach` will be added to `@noverax/courier-nuxt` in parallel with the other 5 framework adapters (`express`, `hono`, `fastify`, `nestjs`, `next`).

In the meantime, run a [standalone Courier server](/docs/deployment/standalone-server) alongside Nuxt for any SSE or WebSocket endpoints, and point `proxyPath.{sse,ws}` at it:

```ts title="composables/useCaller.ts"
import { createProxyCaller } from "@noverax/courier"
import type { api } from "~/lib/sources"

export const caller = createProxyCaller<typeof api>({
  proxyPath: {
    http: "/api/request",                          // handled by Nuxt
    sse:  "http://localhost:4400/api/stream",      // handled by standalone server
    ws:   "ws://localhost:4400/api/ws",            // handled by standalone server
  },
})
```

## Studio integration & `appOrigin` <a id="studio-app-origin"></a>

Wire your Nuxt server into Studio with a single `attachRuntime()` call from a Nitro plugin. It auto-loads `courier.config.ts` from disk, registers your sources, and opens the Studio dev-server connection. The `appOrigin` field for Playground proxy SSE/WS resolution lives in `courier.config.ts.runtime.appOrigin` (or set the `COURIER_APP_URL` env var to override per-environment).

```ts title="server/plugins/courier-studio.ts"
import { attachRuntime } from "@noverax/courier-studio-core/runtime"

export default defineNitroPlugin(async () => {
  if (process.env.NODE_ENV === "production") return
  await attachRuntime()
})
```

Alternatively, set `COURIER_APP_URL` instead of pinning `appOrigin` in the config:

```bash
COURIER_APP_URL=http://localhost:3000 nuxt dev
```

<Callout variant="warn" title="No magic default">
There is no `localhost:3000` auto-fallback. If `appOrigin` is missing, clicking "Subscribe" on an SSE/WS endpoint in Studio Playground proxy mode throws `ConfigurationError("APP_ORIGIN_NOT_CONFIGURED")` with a pointer back to this section. The correct value depends on your runtime — custom port, Docker host, HTTPS, reverse proxy — and a wrong guess would silently route requests to nowhere.
</Callout>

## Project structure

```
composables/
  useCaller.ts              # createProxyCaller<typeof api>()
lib/
  sources.ts                # defineApi + defineGroup + endpoint
  server-caller.ts          # createCaller(api)
server/
  api/
    request.post.ts         # courierHandler()
    dashboard.get.ts        # server-side with createCaller
    posts/[id].get.ts       # dynamic server route
pages/
  posts.vue                 # client-side with useAsyncData
  posts/create.vue          # mutations
  posts/[id].vue            # dynamic page with useFetch
```
