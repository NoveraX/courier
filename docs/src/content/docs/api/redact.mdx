## Import

```ts side="server"
import { redact } from "@noverax/courier/server"
```

A server's code takes `redact` from `@noverax/courier/server`, with the rest of what a server runs. `@noverax/courier/client` leaves it out: no call of a page needs its rules for what a credential looks like, and a bundler that keeps the exports any page of an app uses — Next.js's Turbopack — would load them on every page that imports the client's entry. A page that cuts what it sends elsewhere takes `redact` from the root:

```ts side="page" root="@noverax/courier/client leaves redact out, so a page takes it from the root"
import { redact } from "@noverax/courier"
```

## Signature

```ts
declare function redact(value: string): string
declare function redact(value: Headers): Record<string, string | string[]>
declare function redact(value: Error): Error
declare function redact(value: unknown): unknown
```

`redact` returns what it was given with every credential cut out, and never changes the value itself. Courier's server log passes each line and the error under it through it before writing them down, and Studio cuts by the same rules whatever leaves the page that holds its token. Use it for what your own code sends elsewhere: an error tracker, an audit record, a support ticket.

## What it cuts

| Given | Comes back |
|---|---|
| A text | Without a private key, a JWT, a key in a known provider's format, the value after an authorization scheme, a word that reads as a credential after one that says it is one — `bad credentials …`, `secret …` — the value of a pair whose name says it is secret — `password=`, `"token":`, `api_key` — and a header value the platform repeated as it refused it. An id no such word names — a trace id, a hash — is kept. In every address, the user and password, secret query parameters and a path segment that reads as a token are cut. |
| `Headers` | A record by name. A credential header's value is hidden — `Authorization` keeps its scheme, `Set-Cookie` its name and attributes — and so is the value of a header named as a field that would be hidden, `sid` or `x-otp`; the rest are kept, each read as a text is: a `Location` or a `Link` loses an address's secret parameters. |
| An error | The error itself when it carries nothing to cut. Otherwise a copy that prints as it does: its name, its message and the message its stack starts with cut, the stack's frames kept, its own fields and every error in its `cause` chain read the same way. |
| A list or a record | Read entry by entry: an entry whose name says it is secret — `password`, `token`, `apiKey`, `session`, `otp` — is hidden whole, and one named `key` only when its value reads as a credential. |

A name reads its value alike wherever the two stand — a parameter of an address, a field of a record, a pair in a text or a body, a header — so a call's variables lose whatever the address made of them loses by its names. A name that says its value is a credential hides whatever it is given: a one-time password's few digits, a session's `sid`, a signature's `sig`. `key` alone, which names a sort key or a cache key as often as an API's, hides only a value that reads as a credential: `key: "id"` stays, `key: 123456` does not. An address cuts one thing more, a value that reads as a token under a name that says nothing, `?id=` or `?t=`, as a credential travels in one under any name; a record keeps such a value, an id or a trace id, as a pair in a text does.

```ts side="server"
import { redact } from "@noverax/courier/server"

redact('Headers.set: "Bearer t0k3n\r\nX-Injected: 1" is an invalid header value.')
// → 'Headers.set: "[redacted]" is an invalid header value.'

redact("connect failed for postgres://app:hunter2@db.internal:5432/app")
// → "connect failed for postgres://db.internal:5432/app"

redact({ user: "ana", password: "hunter2", key: "id" })
// → { user: "ana", password: "[redacted]", key: "id" }
```

## Limits

Redacting costs a bounded amount whatever it is handed: a text past 8,192 characters is cut short where a word ends, a value is read sixteen levels deep, and a list or a record keeps its first thousand entries and counts the rest. Where a value holds itself, or lies deeper than that, `[…]` stands in its place. A part that cannot be read — a getter that throws, a proxy whose trap does — is `[unreadable]`, and the rest of the value is read as it is: `redact` never throws, and neither does the server's log that calls it.

The rules read credentials by their shape and their names. A secret written as ordinary prose — a password in a sentence with nothing to mark it — reads as prose; keep such text out of errors.
