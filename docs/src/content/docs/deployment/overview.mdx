## Deployment Models

Courier supports two deployment models for realtime features (SSE and WebSocket):

| Model | Best For | Packages |
|-------|----------|----------|
| **Framework adapter** | Apps already using Express, Fastify, Hono, or NestJS | `@noverax/courier-express`, `-fastify`, `-hono`, `-nestjs` |
| **Standalone server** | Next.js (WS needs separate process), dedicated realtime service | `@noverax/courier-server` |

<Callout variant="info" title="Next.js limitation">
  Next.js App Router cannot handle WebSocket upgrades. Use `sseRoute()` for SSE, and run a separate `@noverax/courier-server` for WebSocket support.
</Callout>

## Single vs Multi-Replica

| | Single Replica | Multi-Replica |
|---|---|---|
| **Adapters** | Memory (built-in, zero config) | Redis (`@noverax/courier-redis`) |
| **SSE resume** | `createMemoryStream()` | `createRedisStream()` |
| **WS broadcast** | `createMemoryPubSub()` | `createRedisPubSub()` |
| **Presence** | `createMemoryPresence()` | `createRedisPresence()` |
| **Use case** | Development, single-process prod | K8s, Docker Swarm, any horizontal scaling |

Memory adapters are the default — they work out of the box with zero configuration. Switch to Redis adapters when you need multiple server instances sharing state.

## Decision Tree

1. **Do you need realtime?** (SSE or WebSocket)
   - No → standard `apiRoute()` / `courierHandler()` is enough
   - Yes → continue

2. **Which framework?**
   - Next.js → `sseRoute()` for SSE + `@noverax/courier-server` for WS
   - Express / Fastify / Hono / NestJS → framework adapters handle both SSE and WS natively
   - No framework → `@noverax/courier-server` standalone

3. **How many replicas?**
   - Single → memory adapters (default)
   - Multiple → Redis adapters + sticky sessions

## Health Checks

Every Courier server (standalone or framework adapter) provides two health endpoints:

- **`GET /health`** — always returns `200 { "status": "ok" }` (liveness probe)
- **`GET /readyz`** — returns `200` when ready, `503` during shutdown (readiness probe)

Use these with Kubernetes, Docker health checks, or load balancer configuration.
