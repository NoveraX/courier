The `@noverax/courier-express` adapter provides a handler for Express that serves as the Courier proxy route.

## Installation

```bash
npm install @noverax/courier @noverax/courier-express express cors
npm install -D @types/express @types/cors
```

## Define your API sources

```ts title="lib/sources.ts"
import { courier, defineApi, defineGroup } from "@noverax/courier/define"

const { endpoint } = courier()

type User = { id: number; name: string; email: string }

const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: endpoint.get("").response<User[]>(),
    getById: endpoint.get(":id").variables<{ id: number }>().response<User>(),
    create: endpoint.post("").variables<{ name: string; email: string }>().response<User>(),
    remove: endpoint.del(":id").variables<{ id: number }>().response<null>(),
  },
})

export const api = defineApi({
  baseURL: process.env.API_URL ?? "http://localhost:4000",
  groups: { users },
})

export const sources = { myApi: api }
```

## Setup

Create an Express server with the Courier handler:

```ts title="server.ts"
import express from "express"
import cors from "cors"
import { registerSources } from "@noverax/courier"
import { courierHandler } from "@noverax/courier-express"
import { sources } from "./lib/sources"

registerSources(sources)

const app = express()

app.use(cors({ origin: "http://localhost:5173", credentials: true }))
app.use(express.json())

// Mount the Courier proxy route
app.all("/api/request", courierHandler())

app.listen(3001, () => {
  console.log("Server running on http://localhost:3001")
})
```

`registerSources(sources)` populates the in-process registry that `courierHandler()` reads at request time. The adapter is zero-arg — pass only behavioral options like `allowedOrigins` or `sseHeaders`. When you wire Studio on top (see below), `attachRuntime()` auto-loads `courier.config.ts` and calls `registerSources()` for you, so you can drop the manual call.

## With existing Express app

If you already have an Express server, add the Courier handler alongside your existing routes:

```ts title="server.ts"
import express from "express"
import cors from "cors"
import { registerSources } from "@noverax/courier"
import { courierHandler } from "@noverax/courier-express"
import { sources } from "./lib/sources"

registerSources(sources)

const app = express()

app.use(cors({ origin: "http://localhost:5173", credentials: true }))
app.use(express.json())

// Your existing routes
app.get("/health", (req, res) => {
  res.json({ status: "ok" })
})

app.get("/api/stats", (req, res) => {
  res.json({ uptime: process.uptime() })
})

// Add Courier proxy route
app.all("/api/request", courierHandler())

app.listen(3001)
```

<Callout variant="warning" title="Body parsing">
Do **not** apply `express.json()` (or any other body-parsing middleware like `express.urlencoded()` or `multer`) to the `/api/request` route — the Courier handler reads the raw request body itself, and a pre-parsed body will be consumed before it gets there. Apply body parsers only to your other application routes.
</Callout>

## CORS configuration

For production, restrict the allowed origins:

```ts title="server.ts"
import express from "express"
import cors from "cors"
import { registerSources } from "@noverax/courier"
import { courierHandler } from "@noverax/courier-express"
import { sources } from "./lib/sources"

registerSources(sources)

const app = express()

app.use(
  cors({
    origin: process.env.ALLOWED_ORIGINS?.split(",") ?? "http://localhost:5173",
    credentials: true,
  })
)
app.use(express.json())

app.all("/api/request", courierHandler())

app.listen(Number(process.env.PORT) || 3001)
```

<Callout variant="info" title="Credentials">
Set `credentials: true` in your CORS config if your backend uses cookies for authentication. The Courier proxy route forwards cookies from the browser to your backend automatically.
</Callout>

## Studio integration & `appOrigin` <a id="studio-app-origin"></a>

Wire your Express server into Studio with a single `attachRuntime()` call. It auto-loads `courier.config.ts` from disk, registers your sources, and opens the Studio dev-server connection. The `appOrigin` field for Playground proxy SSE/WS resolution lives in `courier.config.ts.runtime.appOrigin` (or set the `COURIER_APP_URL` env var to override per-environment).

```ts title="server.ts"
import express from "express"
import { courierHandler } from "@noverax/courier-express"
import { attachRuntime } from "@noverax/courier-studio-core/runtime"

if (process.env.NODE_ENV !== "production") {
  await attachRuntime()
}

const app = express()
app.use(express.json())
app.all("/api/request", courierHandler())

app.listen(3001)
```

Alternatively, set `COURIER_APP_URL` instead of pinning `appOrigin` in the config:

```bash
COURIER_APP_URL=http://localhost:3001 node server.js
```

<Callout variant="warn" title="No magic default">
There is no `localhost:3001` auto-fallback. If `appOrigin` is missing, clicking "Subscribe" on an SSE/WS endpoint in Studio Playground proxy mode throws `ConfigurationError("APP_ORIGIN_NOT_CONFIGURED")` with a pointer back to this section. The correct value depends on your runtime — custom port, Docker host, HTTPS, reverse proxy — and a wrong guess would silently route requests to nowhere.
</Callout>

## Client-side setup

On the client, point your caller to this server's proxy URL. Choose the guide for your frontend:

- [React (Vite / CRA)](/docs/frameworks/react) — `createProxyQueryCaller` with React Query hooks
- [Vue](/docs/frameworks/vue) — `createProxyCaller` with composables
- [Next.js](/docs/frameworks/nextjs) — full-stack with `apiRoute` and `createProxyQueryCaller`
- [Nuxt](/docs/frameworks/nuxt) — full-stack with `courierHandler` and `createProxyCaller`

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/courier"
import type { api } from "../shared/sources"

export const caller = createProxyCaller<typeof api>({
  proxyPath: { http: "http://localhost:3001/api/request" },
})
```
