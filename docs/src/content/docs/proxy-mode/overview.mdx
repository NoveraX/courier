## What is proxy mode?

In proxy mode, browser requests never reach your backend directly. Instead, every request goes through a Next.js API route that acts as a reverse proxy:

1. The browser calls `createClientRequest`, which POSTs to `/api/request`
2. The API route (`apiRoute`) validates the origin, parses the payload, and calls `executeRequest`
3. `executeRequest` looks up the source, group, and method, creates an `HttpClient`, and makes the real HTTP call to your backend
4. The response is forwarded back to the browser

```bash title="Architecture"
┌──────────────────────────────────────────────────────────────┐
│  Browser (Client Component)                                  │
│                                                              │
│  createClientRequest<Sources>()                              │
│       │                                                      │
│       ▼                                                      │
│  ky.post("/api/request", { json: { source, group, query } }) │
└──────────────────┬───────────────────────────────────────────┘
                   │  POST /api/request
                   ▼
┌──────────────────────────────────────────────────────────────┐
│  Next.js API Route (Server)                                  │
│                                                              │
│  apiRoute(sources) → { POST }                                │
│       │  ✓ origin validation                                 │
│       │  ✓ cookie forwarding                                 │
│       │  ✓ header whitelisting                               │
│       ▼                                                      │
│  createRequest(sources, body, context)                        │
│       │                                                      │
│       ▼                                                      │
│  Instance → ky → GET/POST/PUT/PATCH/DELETE                   │
└──────────────────┬───────────────────────────────────────────┘
                   │  HTTP request
                   ▼
┌──────────────────────────────────────────────────────────────┐
│  Backend API (any REST server)                               │
│  e.g. Express, FastAPI, Rails, Go                            │
└──────────────────────────────────────────────────────────────┘
```

## Why use proxy mode?

- **Hide API secrets** — your backend URL, API keys, and tokens stay on the server. The browser only sees `/api/request`.
- **Bypass CORS** — the proxy route runs on the same origin as your frontend, so there are no cross-origin restrictions.
- **Forward cookies** — credentials are included automatically (`credentials: "include"` by default), and `set-cookie` headers from the backend are passed through.
- **Centralized error handling** — the API route catches errors and returns consistent JSON responses with proper HTTP status codes.
- **Request/response hooks** — use `onRequest`, `onResponse`, and `onError` hooks at the source level to transform, log, or enrich every request.

## Request flow

Here is the complete flow from a browser call to the backend response:

```ts title="Request lifecycle"
// 1. Browser — call a typed request
const request = createClientRequest<Sources>()
const user = await request("myApi")("users:getById", { id: 5 })

// 2. Under the hood, Nexus sends:
//    POST /api/request
//    { source: "myApi", group: "users", query: "getById", variables: { id: 5 } }

// 3. API route receives the POST, finds the source and method,
//    creates an Instance, and calls: GET {baseURL}/users/5

// 4. Response flows back: backend → API route → browser
```

## Security

Proxy mode includes two built-in security layers: origin validation and header whitelisting.

### Origin validation

The API route rejects requests whose `Origin` header does not match the request URL origin. This prevents third-party sites from calling your proxy:

```typescript
// src/next/apiRoute.ts — built-in origin check
const origin = request.headers.get("origin")

if (!origin || new URL(request.url).origin !== origin) {
  return NextResponse.json(
    { success: false, message: "Origin mismatch" },
    { status: 403 }
  )
}
```

### Header whitelisting

Not all browser headers are forwarded to the backend. Nexus uses a whitelist to prevent leaking internal headers while passing through the ones your backend needs:

```typescript
// Only these headers are forwarded from the browser to the backend:
const whitelistedHeaders = [
  "referer",
  "origin",
  "authorization",
  "user-agent",
  "cookie",
  "x-forwarded-for",
  "x-forwarded",
  "x-real-ip",
  "x-request-id",
  // ... plus custom headers via extraHeaders option
]
```

<Callout variant="tip" title="Custom headers">
Need additional headers forwarded? Use the `extraHeaders` option in your `Datasource` class constructor to extend the whitelist.
</Callout>

## When to use proxy vs direct mode

Use **proxy mode** for client components where the browser initiates the request. Use **direct mode** for server components and server actions where the server calls the backend directly with zero overhead.

```ts title="Comparison"
// Proxy mode — browser cannot see API_URL or secrets
// Browser → POST /api/request → Server → GET https://internal-api.company.com/users
const request = createClientRequest<Sources>()
const users = await request("myApi")("users:getAll")

// Direct mode — server calls backend directly, no proxy hop
// Server → GET https://internal-api.company.com/users
const users = await directRequest("myApi")("users:getAll")
```

<Callout variant="info" title="Same API definitions">
Both modes share the same `Datasource` and `EndpointGroup` classes. You define your API once and use it from both client and server code with full type safety.
</Callout>
