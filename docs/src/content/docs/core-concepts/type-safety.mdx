## Overview

Nexus provides full type safety across the entire request lifecycle: from your API definition to the data in your components. No code generation, no schema files, no build step. TypeScript functions are the single source of truth.

## The endpoint Generic

Type safety starts with `endpoint<R, V>()`. Every endpoint declares two type parameters:

- `R` — the response type (what the backend returns)
- `V` — the variables type (what the caller must pass). Defaults to `undefined`.

```ts title="api/users.ts"
import { defineGroup, endpoint } from "@noverax/nexus/define"

type User = { id: string; name: string; email: string }
type UserList = { data: User[]; total: number }

export const users = defineGroup({
  prefix: "users",
  endpoints: {
    // endpoint<R> — R is the response type, no variables needed
    getAll: endpoint<UserList>()((http) => http.get()),

    // endpoint<R, V> — R is the response type, V is the variables type
    getById: endpoint<User, { id: string }>()((http, vars) => http.get(":id", vars)),

    // V determines what the caller must pass
    create: endpoint<User, { name: string; email: string }>()((http, vars) => http.post("", vars)),
  },
})
```

## The Inference Chain

Nexus uses TypeScript's type inference to propagate types through a curried function chain:

```typescript
// 1. You define the source
export const sources = { api }
export type Sources = typeof sources

// 2. You create a typed caller
const { useQuery, useMutation } = createQueryCaller<Sources>()

// 3. TypeScript infers everything at the call site
const { data } = useQuery("api", "users:getAll")
//      ^? UserList — inferred from endpoint<UserList>

const { data } = useQuery("api", "users:getById", {
  variables: { id: "5" },
  //           ^? { id: string } — inferred from endpoint<User, { id: string }>
})

const { mutate } = useMutation("api", "users:create")
mutate({ name: "Jane", email: "jane@test.com" })
//      ^? { name: string; email: string } — inferred from endpoint
```

<Callout variant="tip" title="No manual type annotations">
You never need to write `useQuery<UserList>("api", "users:getAll")`. The response type is inferred automatically. Types stay in one place and are never duplicated.
</Callout>

## Endpoint Key Literals

The `"group:method"` key is a TypeScript string literal type. This gives you autocomplete and compile-time validation:

```typescript
// Source names are validated
call("api")("users:getAll")         // valid
call("unknown")("users:getAll")     // Type error: "unknown" is not a valid source

// Endpoint keys are validated
call("api")("users:getAll")         // valid
call("api")("users:unknown")        // Type error: "unknown" is not a method on users
call("api")("fake:getAll")          // Type error: "fake" is not a group
```

## Variables Enforcement

TypeScript enforces whether variables are required, optional, or forbidden:

```typescript
// No variables — V defaults to undefined
endpoint<User[]>()((http) => http.get())

call("api")("users:getAll")                          // valid
call("api")("users:getAll", { page: 1 })             // Type error — no variables expected

// Required variables
endpoint<User, { id: string }>()((http, vars) => http.get(":id", vars))

call("api")("users:getById")                         // Type error — variables required
call("api")("users:getById", { id: 123 })            // Type error — id must be string
call("api")("users:getById", { id: "5" })            // valid
```

## Pattern: Well-Typed Endpoints

For the best DX, define domain types explicitly and use utility types:

```ts title="api/products.ts"
import { defineGroup, endpoint } from "@noverax/nexus/define"

type Product = { id: string; name: string; price: number; category: string }

type ProductFilters = {
  category?: string
  minPrice?: number
  maxPrice?: number
  page?: number
}

type CreateProductVars = Omit<Product, "id">
type UpdateProductVars = { id: string } & Partial<CreateProductVars>

export const products = defineGroup({
  prefix: "products",
  endpoints: {
    list:    endpoint<Product[], ProductFilters>()((http) => http.get()),
    getById: endpoint<Product, { id: string }>()((http, vars) => http.get(":id", vars)),
    create:  endpoint<Product, CreateProductVars>()((http, vars) => http.post("", vars)),
    update:  endpoint<Product, UpdateProductVars>()((http, vars) => http.patch(":id", vars)),
    remove:  endpoint<null, { id: string }>()((http, vars) => http.del(":id", vars)),
  },
})

// Everything flows automatically:
// useQuery("api", "products:list", { variables: { category: "shoes" } })
//                                                ^? ProductFilters
// → data is Product[]
```

## Schema-Inferred Types

When using runtime validation, types can be inferred from schemas — no manual generics needed:

```typescript
import { z } from "zod"

const UserSchema = z.object({ id: z.string(), name: z.string(), email: z.string() })

// Types inferred from schema — no endpoint<User>() needed
endpoint({ response: z.array(UserSchema) })((http) => http.get())
// → response type is { id: string; name: string; email: string }[]
```
