## What is direct mode?

In **direct mode**, your server-side code calls the backend directly without routing through an API proxy. The request flow is straightforward:

```
createDirectRequest → createRequest → HttpClient → ky → backend
```

There is no intermediate HTTP hop, no serialization through an API route, and no exposure to the client bundle. Your backend URL, API keys, and other secrets remain on the server.

<Callout variant="info" title="Same sources, different transport">
Direct mode uses the same `Datasource` and `EndpointGroup` classes as proxy mode. You define your API structure once and use it from both client and server code.
</Callout>

## When to use direct mode

Use direct mode whenever your code runs on the server:

- **React Server Components (RSC)** — fetch data at render time with zero client JavaScript
- **Server Actions** — handle form submissions and mutations without writing API routes
- **API Routes** — when your Next.js route handler needs to aggregate data from your backend
- **Middleware** — validate tokens or fetch user data before routing

## Benefits over proxy mode

- **Lower latency** — eliminates the extra HTTP hop through `/api/request`
- **Server-only secrets** — backend URLs and API keys never appear in the client bundle
- **No client JavaScript** — RSC data fetching adds zero bytes to the browser bundle
- **Simpler error handling** — errors stay on the server, no need to serialize them for the client

## Quick setup

Create a direct request client by passing your sources to `createDirectRequest`:

```ts title="lib/direct-request.ts"
// lib/direct-request.ts
import { createDirectRequest } from "@noverax/nexus/direct"
import { sources } from "@/api"

export const directRequest = createDirectRequest(sources)
```

## Usage in Server Components

Call the direct request client in any `async` server component. The data is fetched at render time on the server:

```ts title="app/dashboard/page.tsx"
// app/dashboard/page.tsx — React Server Component
import { directRequest } from "@/lib/direct-request"

export default async function DashboardPage() {
  const users = await directRequest("myApi")("users:getAll", { page: 1, limit: 10 })

  return (
    <ul>
      {users.data.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  )
}
```

## Usage in Server Actions

Server Actions use the same direct request client. Pass `headers()` as context to forward authentication cookies:

```ts title="app/actions/users.ts"
// app/actions/users.ts — Server Action
"use server"

import { headers } from "next/headers"
import { revalidatePath } from "next/cache"
import { directRequest } from "@/lib/direct-request"

export async function createUser(data: { name: string; email: string }) {
  const user = await directRequest("myApi")(
    "users:create",
    data,
    { headers: await headers() }
  )

  revalidatePath("/dashboard")
  return user
}
```

## Context and cookie forwarding

In direct mode, the browser's cookies are not automatically available. To forward authentication headers, pass a `Context` object with the current `headers()`:

```ts title="app/profile/page.tsx"
// app/profile/page.tsx — forwarding cookies for auth
import { headers } from "next/headers"
import { directRequest } from "@/lib/direct-request"

export default async function ProfilePage() {
  // Pass headers so cookies (auth tokens) reach the backend
  const profile = await directRequest("myApi")(
    "users:me",
    undefined,
    { headers: await headers() }
  )

  return <h1>Welcome, {profile.name}</h1>
}
```

<Callout variant="tip" title="Header whitelist">
Nexus only forwards safe headers from the context: `authorization`, `cookie`, `user-agent`, `x-forwarded-*`, `x-real-ip`, and others. Custom headers from `defaults.headers` are always included.
</Callout>

## Security considerations

Direct mode runs exclusively on the server. This means:

- Your backend URL (`API_URL`) is never sent to the browser
- API keys and tokens in `defaults.headers` stay server-side
- Source code for `createDirectRequest` is tree-shaken from the client bundle
- Error details (stack traces, internal URLs) never leak to the client

<Callout variant="warning" title="Don't import direct-request.ts in client components">
If you import your direct request client in a `"use client"` file, Next.js will try to bundle your source definitions (including `process.env.API_URL`) into the client. Keep direct request imports in server-only files.
</Callout>
