## Recommended file structure

Keep your API definitions separate from your UI code. A typical Nexus project follows this structure:

```bash
src/
├── api/
│   ├── index.ts          # Datasource classes + sources export
│   ├── users.ts          # Users EndpointGroup
│   ├── posts.ts          # Posts EndpointGroup
│   └── files.ts          # Files EndpointGroup
├── lib/
│   ├── request.ts        # createQueryRequest (proxy + React Query)
│   └── direct-request.ts # createDirectRequest (server-side)
├── app/
│   ├── api/
│   │   └── request/
│   │       └── route.ts  # apiRoute handler
│   ├── layout.tsx
│   └── page.tsx
└── ...
```

## Source definitions

The `api/` directory contains your API structure. The main file creates `Datasource` instances with groups, and each group lives in its own file:

```ts title="api/index.ts"
// api/index.ts
import { Datasource } from "@noverax/nexus/datasource"
import { Users } from "./users"
import { Posts } from "./posts"
import { Files } from "./files"

const API_URL = process.env.API_URL ?? "http://localhost:4000"

const groups = {
  users: new Users(),
  posts: new Posts(),
  files: new Files(),
}

class MyApi extends Datasource<typeof groups> {
  constructor() {
    super({ baseURL: API_URL, groups })
  }
}

export const sources = { myApi: new MyApi() }
export type Sources = typeof sources
```

```ts title="api/users.ts"
// api/users.ts
import { type Endpoint, EndpointGroup } from "@noverax/nexus/datasource"

type User = { id: number; name: string; email: string }

export class Users extends EndpointGroup {
  constructor() {
    super({ prefix: "users" })
  }

  getAll: Endpoint<User[]> = ({ get }) => get()
  getById: Endpoint<User, { id: number }> = ({ get }) => get(":id")
  create: Endpoint<User, { name: string; email: string }> = ({ post }) => post()
  update: Endpoint<User, { id: number; name: string }> = ({ put }) => put(":id")
  remove: Endpoint<null, { id: number }> = ({ del }) => del(":id")
}
```

<Callout variant="tip" title="One group per file">
Keeping each `EndpointGroup` in its own file makes it easy to find and modify endpoints. The types stay co-located with the methods that use them.
</Callout>

## Client setup files

Create two files in `lib/` — one for proxy mode (client components) and one for direct mode (server components):

```ts title="lib/request.ts"
// lib/request.ts
import { createQueryRequest } from "@noverax/nexus/query"
import type { Sources } from "@/api"

export const { useQuery, useMutation, request } = createQueryRequest<Sources>()
```

```ts title="lib/direct-request.ts"
// lib/direct-request.ts
import { createDirectRequest } from "@noverax/nexus/direct"
import { sources } from "@/api"

export const directRequest = createDirectRequest(sources)
```

And the API route handler that the proxy client sends requests through:

```ts title="app/api/request/route.ts"
// app/api/request/route.ts
import { apiRoute } from "@noverax/nexus/next/apiRoute"
import { sources } from "@/api"

export const { POST } = apiRoute(sources)
```

## Multiple backends

If your app talks to multiple backend services, create a separate `Datasource` class for each one. They can all be passed to the same sources object:

```ts title="api/index.ts"
// api/index.ts
import { Datasource } from "@noverax/nexus/datasource"
import { Users } from "./users"
import { Products } from "./products"

const groups = { users: new Users() }
const productGroups = { products: new Products() }

class MainApi extends Datasource<typeof groups> {
  constructor() {
    super({
      baseURL: process.env.API_URL ?? "http://localhost:4000",
      groups,
    })
  }
}

class PaymentApi extends Datasource<typeof productGroups> {
  constructor() {
    super({
      baseURL: process.env.PAYMENT_API_URL ?? "http://localhost:5000",
      groups: productGroups,
    })
  }
}

export const sources = {
  mainApi: new MainApi(),
  paymentApi: new PaymentApi(),
}

export type Sources = typeof sources
```

Both sources share the same proxy route and direct client. TypeScript enforces that you use the correct group names for each source:

```ts
// Fully typed — TypeScript knows which groups belong to which source
const { data: users } = useQuery("mainApi", "users:getAll")
const { data: products } = useQuery("paymentApi", "products:list")
```

## Environment variables

Backend URLs should always be server-side environment variables (no `NEXT_PUBLIC_` prefix). The proxy route keeps them hidden from the browser:

```bash title=".env.local"
# .env.local
API_URL=http://localhost:4000

# Multiple backends
PAYMENT_API_URL=http://localhost:5000

# Optional: custom proxy route path
# NEXT_PUBLIC_REQUEST_PAGE=api/my-proxy
```

<Callout variant="warning" title="Never expose API_URL to the client">
In proxy mode, the browser only talks to `/api/request`. Your backend URL, API keys, and other secrets stay on the server.
</Callout>
