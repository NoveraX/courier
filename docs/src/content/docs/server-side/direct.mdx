## API signature

`createDirectRequest` accepts your sources object and optional defaults. It returns a curried function that selects a source, then executes a query:

```ts title="@noverax/nexus/direct"
import { createDirectRequest } from "@noverax/nexus/direct"

// Full signature
function createDirectRequest<T extends Sources>(
  sources: T,
  defaults?: DirectRequestDefaults
): RequestFn<T, true>
```

## DirectRequestDefaults

The optional second argument configures defaults applied to every request made through this client:

```ts
type DirectRequestDefaults = {
  // Request timeout in milliseconds
  timeout?: number
  // Headers sent with every request
  headers?: Record<string, string>
  // Called when any request fails
  onError?: (error: HTTPError) => void | Promise<void>
  // Called when any request succeeds
  onSuccess?: (data: unknown) => void | Promise<void>
}
```

These defaults are merged with per-request options. Per-request headers are merged (not replaced), while `timeout` is overridden if specified per-request.

```ts title="lib/direct-request.ts"
// lib/direct-request.ts
import { createDirectRequest } from "@noverax/nexus/direct"
import { sources } from "@/api"

export const directRequest = createDirectRequest(sources, {
  timeout: 10000,
  headers: {
    "X-Service": "my-nextjs-app",
  },
  onError: (error) => {
    console.error(`[API] ${error.response.status}: ${error.message}`)
  },
})
```

<Callout variant="tip" title="Global error logging">
The `onError` callback is useful for centralized error logging. It fires before the error propagates to your component, so you can log to Sentry or a custom service without repeating try/catch blocks.
</Callout>

## Basic usage

The returned function is curried: first select a source, then call a query with optional variables and context:

```ts title="app/users/page.tsx"
// app/users/page.tsx — React Server Component
import { directRequest } from "@/lib/direct-request"

export default async function UsersPage() {
  // Step 1: select the source → returns a curried function
  const request = directRequest("myApi")

  // Step 2: call with query and variables
  const users = await request("users:getAll", { page: 1, limit: 20 })
  //    ^? UserList — fully typed from your Endpoint definition

  // Or chain it in one expression
  const user = await directRequest("myApi")("users:getById", { id: 5 })
  //    ^? User

  return (
    <div>
      <h1>Users ({users.total})</h1>
      <ul>
        {users.data.map((u) => (
          <li key={u.id}>{u.name}</li>
        ))}
      </ul>
    </div>
  )
}
```

## Call signatures

The query function accepts different argument combinations depending on whether your method requires variables and whether you need to pass context:

```ts
// No variables, no context
await directRequest("myApi")("users:getAll")

// With variables, no context
await directRequest("myApi")("users:getById", { id: 5 })

// No variables, with context
await directRequest("myApi")("users:me", undefined, { headers: await headers() })

// With variables and context
await directRequest("myApi")("users:create", { name: "Jane" }, { headers: await headers() })
```

## Context parameter

The `Context` parameter is what makes direct mode different from proxy mode. In proxy mode, cookies are forwarded automatically through the API route. In direct mode, you must pass them explicitly:

```ts
import type { Context } from "@noverax/nexus/direct"

type Context = {
  req?: NextRequest      // Next.js request object
  res?: NextResponse     // Next.js response object
  headers?: Headers      // Headers to forward (cookies, auth)
}
```

### In React Server Components

Use Next.js `headers()` from `next/headers` to get the incoming request headers. This includes cookies, authorization headers, and other browser-sent headers:

```ts title="app/profile/page.tsx"
// app/profile/page.tsx — RSC with authentication
import { headers } from "next/headers"
import { directRequest } from "@/lib/direct-request"

export default async function ProfilePage() {
  // headers() returns the incoming request headers (including cookies)
  const profile = await directRequest("myApi")(
    "users:me",
    undefined,        // no variables needed
    { headers: await headers() }  // forward auth cookies to backend
  )

  return <h1>Welcome, {profile.name}</h1>
}
```

### In API routes

In route handlers, pass the `NextRequest` object directly. Nexus extracts the headers from it:

```ts title="app/api/dashboard/route.ts"
// app/api/dashboard/route.ts — API route with context
import { type NextRequest, NextResponse } from "next/server"
import { directRequest } from "@/lib/direct-request"

export async function GET(req: NextRequest) {
  // Pass the NextRequest directly — headers are extracted automatically
  const stats = await directRequest("myApi")(
    "dashboard:getStats",
    undefined,
    { req }
  )

  return NextResponse.json(stats)
}
```

<Callout variant="info" title="Header whitelist">
When you pass context headers, Nexus only forwards a safe subset: `authorization`, `cookie`, `user-agent`, `x-forwarded-for`, `x-forwarded-host`, `x-forwarded-proto`, `x-real-ip`, and a few others. This prevents accidentally forwarding headers like `host` or `content-length` that would break the backend request.
</Callout>

## Raw data mode

By default, the request returns the parsed JSON body. If you need access to the HTTP status code and response headers, pass `rawData: true` as an option:

```ts
// Access status code and response headers
const result = await directRequest("myApi", { rawData: true })(
  "users:getById",
  { id: 5 }
)

console.log(result.status)   // 200
console.log(result.headers)  // Headers object
console.log(result.data)     // User — still fully typed
```

## Difference from createClientRequest

The key difference is the `Context` parameter. In proxy mode, cookies are forwarded automatically through the browser request. In direct mode, you pass them explicitly:

```ts
// Proxy mode (client components) — no context parameter
const request = createClientRequest<Sources>()
await request("myApi")("users:getAll", { page: 1 })
//                                      ^ variables only

// Direct mode (server components) — context as last argument
const request = createDirectRequest(sources)
await request("myApi")("users:getAll", { page: 1 }, { headers: await headers() })
//                                      ^ variables    ^ context (optional)
```

Internally, `createDirectRequest` sets the `D` (direct) flag to `true`, which changes the type signature to accept the context argument. Both functions call the same `createRequest` core under the hood.

<Callout variant="warning" title="Server-only import">
Never import `createDirectRequest` or your direct request client in `"use client"` files. The sources object contains your `process.env.API_URL`, which would be exposed in the client bundle.
</Callout>
