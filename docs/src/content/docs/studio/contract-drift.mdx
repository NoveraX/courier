A response schema says what an endpoint answers. Its real answers say what it does. Studio watches both: each endpoint with a response schema is **confirmed by traffic** while every answer fits its schema, **drifted from its schema** once an answer does not, or **not observed yet** while no answer was seen. A field the backend started sending, a number that became a string, a field that stopped coming — each shows in the Explorer the moment it happens, before it becomes a bug report.

## What Studio watches

Before the response schema reads an answer, Courier tells Studio its shape: each place in it — `user.id`, `items[].price` — with the JSON types it came as. That is the answer as it came, so Studio sees a field even when the schema drops it; it never sees a value. Studio counts each shape for its endpoint, and sets it beside what the response schema declares:

| Difference | When |
| --- | --- |
| Not in the schema | A field the schema does not name, under an object that takes no unnamed keys. A Zod object drops it, so the app never sees it. Only the outermost such field is named: what lies inside it is part of it. |
| Another type | A field that came as a type the schema does not take there: a number where it declares a string, `null` where it is not nullable. |
| Missing | A field the schema requires — under required objects — that some answers lacked. A field absent because its object was is not named: the object is. |

A record's keys are data, not names: `z.record(z.string(), z.number())` takes any key, and its values are checked against the record's value. An object that takes unnamed keys — `z.looseObject`, `.passthrough()` — takes any field. A place the schema leaves unconstrained takes anything.

## In the Explorer

An endpoint whose answers differ from its schema is marked **drifted** in **Explorer → Endpoints**. Its panel's **Contract** section says how it stands, and for each difference: the field, how it differs, when it was first and last seen, in how many of the answers seen, and the hosts that sent them — your staging API, a mock, production behind a tunnel.

**Declare in its response schema** writes the fields the schema should declare so the answers fit it, for Zod when the schema is Zod's, under the object each goes in; **Copy** takes them to paste into the schema. For a list of products whose items came with a `rating` and a numeric `stock`, they go in the item's object:

```ts
import { z } from "zod"

export const Product = z.object({
  id: z.string(),
  rating: z.number().optional(),
  stock: z.number(),
})
```

- A field not every answer held is optional; one that came as `null` too is nullable.
- A field that came as another type is that type — or the union with the declared one, when some answers still came as it.
- A required field some answers lacked is made optional, an object or a list kept as it is declared: `seller: ….optional()`.

Once the schema is fixed, **Forget what was seen** clears what Studio counted for the endpoint, so its next answers are set beside the schema afresh. Studio checks every answer against the schema that is loaded now: fix the schema, and the differences it settles are gone at once.

## Fix the schema

For a Zod schema, **Fix the schema…** makes the change itself, where the schema is written. Studio follows the endpoint from `courier.config.ts` — through `sources`, its groups and `.response(…)` — to the `z.object({…})` each field belongs in, across the imports between them and `tsconfig` path aliases, through `.extend()`, `z.array()`, `.array()` and the modifiers that keep an object's fields where they are written. It shows the change as a diff of each file it touches:

```diff
 export const Product = z.object({
   id: z.string(),
-  price: z.number().int().optional(),
-  stock: z.number(),
-  seller: Seller,
+  price: z.union([z.number().int(), z.string()]).optional(),
+  stock: z.string(),
+  seller: Seller.optional(),
+  rating: z.number().optional(),
 })
```

- A field the schema does not name is added to its object, optional when not every answer held it.
- A field that came as another type takes it beside its own — `.int()` and the rest of what it constrains kept — or in its place when no answer came as the declared one. Its modifiers stay at its end.
- A required field some answers lacked becomes optional.

**Apply the change** writes it only while it is still the change shown — a file saved since, or answers that changed the fix, show the new change instead — and then runs the config again. A config that does not load, or a change that settles none of the differences it was for, is put back, and Studio says why. The toast that says it was written carries **Undo**, which writes the files back while they still hold what Studio wrote: an edit you made since is yours, and Studio leaves it alone.

A file that follows the project's formatter — Biome, Prettier or ESLint — is formatted once changed; one that does not keeps its layout, so the diff holds the fix alone. Studio changes only files the config loads, inside the project, and only for a page that holds Studio's token. A difference it cannot place — in a schema built by a function, or a field declared through a spread — is listed with why, for you to change; so is a schema written with another library, whose fields **Copy** takes instead.

## How much Studio keeps

What Studio counts stays small however heavy the traffic: an answer's first 1000 places at most, 16 levels deep, an array's first 20 items; 500 fields per endpoint, 10 hosts per field, 1000 endpoints. An answer larger than that is counted as cut, and the Contract section says how many were. Studio counts in memory and writes to `.courier/studio.db` every two seconds, so it costs one write per endpoint, not one per answer.

The counts are kept across restarts, as the rest of what Studio shows is. **Settings → Storage** sizes them as **Answer observations** and clears them with the rest. A stream and a channel have no response schema to set their answers beside, and an endpoint without a response schema has no contract to check.
