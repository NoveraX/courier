## Framework adapters

Install the adapter for your server framework. Each adapter is a thin wrapper around `createHandler` — see the [Server Handler](/docs/proxy-mode/api-route) docs for details.

| Framework | Package | Export |
|-----------|---------|--------|
| **Next.js** | `@noverax/courier-next` | `apiRoute`, `createAction` |
| **Nuxt / Nitro / h3** | `@noverax/courier-nuxt` | `courierHandler` |
| **Express** | `@noverax/courier-express` | `courierHandler` |
| **Hono** | `@noverax/courier-hono` | `courierHandler` |
| **Fastify** | `@noverax/courier-fastify` | `courierPlugin` |
| **NestJS** | `@noverax/courier-nestjs` | `courierMiddleware` |

## React Query integration

For React apps, add the query package for type-safe hooks (`useQuery`, `useMutation`, `useSuspenseQuery`, `useInfiniteQuery`):

```bash
npm install @noverax/courier-react @tanstack/react-query
```

## Studio

Studio inspects requests in development. Its runtime registers your sources
from `courier.config.ts`, and every framework's instrumentation snippet imports
it directly — so it is a dependency of your app, not only of the dev server:

```bash
npm install --save-dev @noverax/courier-studio @noverax/courier-studio-core
```

<Callout variant="info" title="Install only what you use">
All framework packages and integrations are optional. The core `@noverax/courier` package works standalone for direct API calls from any runtime.
</Callout>

## TypeScript configuration

Courier ships type declarations. Enable strict mode for the best type inference:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}
```

## Environment variables

Add your backend API URL as a server-side environment variable:

```bash title=".env.local"
# Your backend API URL (server-side only)
API_URL=http://localhost:4000
```

This is used in your `defineApi` call. In proxy mode, the browser never sees this URL — requests go through your server's proxy route.
