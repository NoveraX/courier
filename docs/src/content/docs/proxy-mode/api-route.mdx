## Overview

`createHandler` creates a universal request handler that acts as the server-side half of proxy mode. It receives requests from `createProxyCaller`, validates them, and forwards them to your backend via `executeRequest`.

```typescript
import { createHandler } from "@noverax/nexus"

const { handle, handleGet, handlePost } = createHandler(sources)
// handle:     (request: Request) => Promise<Response>  — auto-routes GET/POST
// handleGet:  (request: Request) => Promise<Response>  — query endpoints
// handlePost: (request: Request) => Promise<Response>  — mutations + data
```

The handler works with Web Standard `Request`/`Response` objects, making it compatible with any JavaScript runtime and framework.

## Setup

### Step 1: Define your sources

The sources object maps source names to API definitions created with `defineApi`:

```ts title="api/index.ts"
import { defineApi, defineGroup, endpoint } from "@noverax/nexus/define"
import type { Endpoint } from "@noverax/nexus/define"

type User = { id: number; name: string; email: string }
type Post = { id: number; title: string; body: string }

const users = defineGroup({
  prefix: "users",
  endpoints: {
    getAll: endpoint<User[]>()((http) => http.get()),
    getById: endpoint<User, { id: number }>()((http, vars) => http.get(":id", vars)),
  },
})

const posts = defineGroup({
  prefix: "posts",
  endpoints: {
    list: endpoint<Post[]>()((http) => http.get()),
    create: endpoint<Post, { title: string }>()((http, vars) => http.post("", vars)),
  },
})

const api = defineApi({
  baseURL: process.env.API_URL ?? "http://localhost:4000",
  groups: { users, posts },
})

export const sources = { api }
export type Sources = typeof sources
```

<Callout variant="tip" title="All adapters use createHandler">
Every framework adapter is a thin wrapper around `createHandler()` from `@noverax/nexus`. Sources are read lazily from the core global registry populated by `registerSources()` (or by `attachRuntime()` auto-loading `nexus.config.ts`). If your framework is not listed, use `createHandler` directly with Web Standard `Request`/`Response`.
</Callout>

## How it works

All adapters delegate to `createHandler()`, which returns three methods:

- **`handle(request)`** — auto-routes GET and POST, returns 405 for other methods
- **`handleGet(request)`** — parses query parameters (`_s`, `_g`, `_m` + variables) for cacheable read endpoints
- **`handlePost(request)`** — validates origin, parses JSON or FormData body for mutations

## Origin validation

Every POST request is checked to ensure the `Origin` header matches the request URL origin. This prevents cross-site request forgery and unauthorized third-party access:

```typescript
// Built-in origin validation (POST only)
const origin = request.headers.get("origin")

if (!origin || new URL(request.url).origin !== origin) {
  return Response.json(
    { success: false, message: "Origin mismatch" },
    { status: 403 }
  )
}

// GET requests skip origin validation (cacheable, no side effects)
```

## Content-Type handling

The POST handler accepts two content types and rejects everything else:

```typescript
// The handler accepts two content types:

// 1. application/json — standard requests
// Body: { source, group, method, variables, options }

// 2. multipart/form-data — file uploads
// Fields: _source, _group, _method, _options + user data/files

// Anything else returns 415 Unsupported Media Type
// { success: false, message: "Unsupported Content-Type" }
```

## Cookie forwarding

Cookies are forwarded in both directions automatically. Browser cookies are included in the proxied request (via the header whitelist), and `set-cookie` headers from the backend are passed through to the browser response:

```typescript
// Cookies are forwarded automatically:
// Browser → proxy handler → backend (via header whitelist)
// Backend → proxy handler → browser (set-cookie headers passed through)

// Browser side — credentials: "include" is the default
const caller = createProxyCaller<typeof api>()
// Cookies are sent with every request automatically
```

<Callout variant="info" title="set-cookie handling">
Nexus uses `getSetCookie()` to correctly handle multiple `set-cookie` headers, avoiding the common bug of splitting cookie values on commas.
</Callout>

## Error responses

The handler returns consistent JSON error responses with appropriate HTTP status codes:

```typescript
// Error responses follow a consistent format:

// HTTP errors from the backend:
// Status: forwarded from backend (e.g., 404, 422, 500)
// Body:   parsed JSON from backend response

// Validation errors (missing source, endpoint not found):
// Status: 400
// Body:   { success: false, message: "[api][users][getById]: method not found" }

// Origin mismatch:
// Status: 403
// Body:   { success: false, message: "Origin mismatch" }

// Invalid JSON body:
// Status: 400
// Body:   { success: false, message: "Invalid JSON body" }
```
