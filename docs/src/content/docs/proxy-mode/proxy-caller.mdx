## Overview

`createProxyCaller` creates a curried function that POSTs to your server proxy endpoint. It is the primary way to make requests from client components in proxy mode.

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/nexus"
import type { Sources } from "@/api"

// createProxyCaller<T>(defaults?) returns CallerFn<T>
const call = createProxyCaller<Sources>()

// Curried usage:
const result = await call("api")("users:getById", { id: 5 })
//                        ^? source  ^? endpoint key   ^? variables
```

The generic parameter `Sources` provides full type inference for source names, group names, endpoint names, variables, and response types.

## Defaults

Pass a `ProxyCallerDefaults` object to configure global behavior for all requests created by this factory:

```typescript
type ProxyCallerDefaults = {
  // Full URL path to the proxy endpoint — default: "/api/request"
  proxyUrl?: string

  // Request timeout in milliseconds
  timeout?: number

  // Cookie behavior — default: "include"
  credentials?: RequestCredentials

  // Extra headers sent with every proxy request
  headers?: Record<string, string>

  // Called on every failed request
  onError?: (error: HTTPError) => void | Promise<void>

  // Called on every successful request
  onSuccess?: (data: unknown) => void | Promise<void>
}
```

## Complete setup

A typical setup creates a single caller instance and exports it for use across all client components:

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/nexus"
import type { Sources } from "@/api"

export const call = createProxyCaller<Sources>({
  timeout: 30_000,
  credentials: "include",
  headers: {
    "x-app-version": "1.0.0",
  },
  onError: (error) => {
    if (error.status === 401) {
      window.location.href = "/login"
    }
  },
})
```

<Callout variant="tip" title="One instance per app">
Create `createProxyCaller` once in a shared module. All client components import from the same file, ensuring consistent defaults and callbacks.
</Callout>

## Endpoint key convention

The endpoint key tells Nexus which endpoint to call. It uses the `"group:method"` format:

```ts title="Usage examples"
// "groupName:endpointName"
await call("api")("users:getAll")
await call("api")("users:getById", { id: 5 })
await call("api")("posts:create", { title: "Hello", body: "World" })
```

## Curried usage

The first call selects the source and optional per-request options. The second call specifies the endpoint and variables:

```ts title="Curried calls"
// Basic — source only
await call("api")("users:getAll")

// With per-request options
await call("api", { rawData: true })("users:getById", { id: "5" })

// Store the source selector for reuse
const api = call("api")
const users = await api("users:getAll")
const user = await api("users:getById", { id: 5 })
```

## Body composition

How the request body is built depends on the type of variables you pass:

```ts title="JSON vs FormData"
// JSON body (default for objects)
// Sends: POST /api/request
// Body:  { source: "api", group: "users", method: "create", variables: { name: "Jane" } }
await call("api")("users:create", { name: "Jane" })

// FormData body (when variables is FormData)
// Sends: POST /api/request (multipart/form-data)
// Body:  _source=api, _group=users, _method=create, _options={...}, name=Jane, avatar=File
const formData = new FormData()
formData.append("name", "Jane")
formData.append("avatar", fileInput.files[0])
await call("api")("users:create", formData)
```

<Callout variant="info" title="FormData meta fields">
When sending FormData, Nexus appends metadata as special fields: `_source`, `_group`, `_method`, and `_options`. Your actual variables are appended alongside them. The server handler strips these meta fields before passing variables to your endpoint.
</Callout>

## Per-request options

You can pass options to the source selector (the first curried call) to override defaults for a specific request chain:

```ts title="Per-request options"
// Per-request options (second argument of the source selector)
const fetchUser = call("api", {
  timeout: 5000,
  signal: abortController.signal,
  cache: "no-store",
})

const user = await fetchUser("users:getById", { id: 5 })
```

## Global callbacks

The `onError` and `onSuccess` callbacks run for every request made by this factory. Use them for cross-cutting concerns like authentication redirects or logging:

```ts title="Global error handling"
const call = createProxyCaller<Sources>({
  onSuccess: (data) => {
    // Called after every successful response
    console.log("Response:", data)
  },
  onError: (error) => {
    // Called after every failed response
    // error.status  — HTTP status code
    // error.data    — parsed response body
    // error.headers — response headers

    if (error.status === 401) {
      window.location.href = "/login"
    }

    if (error.status === 429) {
      toast.error("Too many requests. Please wait.")
    }
  },
})
```

## Custom proxy endpoint

By default, requests are sent to `/api/request`. Change it by passing `proxyUrl` in the defaults:

```ts title="lib/caller.ts"
export const call = createProxyCaller<Sources>({
  proxyUrl: "/api/my-proxy",
})
```

<Callout variant="warning" title="Match your server handler">
If you change the proxy URL, make sure your server handler is mounted at the same path. For example, `proxyUrl: "/api/my-proxy"` requires the server handler at `/api/my-proxy`.
</Callout>
