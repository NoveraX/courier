## Overview

Every API call in Courier follows a well-defined lifecycle. There are two transport modes — **Direct** and **Proxy** — but both converge on the same internal `executeRequest` function. Understanding this flow helps you debug issues, write middleware, and choose the right mode for your use case.

## Two Modes

| Factory | Mode | Runtime | Use Case |
|---------|------|---------|----------|
| `createCaller(api)` | Direct | Any (Node.js, Bun, Deno, browser) | Server Components, Server Actions, scripts, CLI |
| `createProxyCaller<typeof api>("api")` | Proxy | Browser | Client Components — hides backend URL, handles CORS, forwards cookies |

## Request Flow

```
Direct:  createCaller(api) → caller.users.getAll() → executeRequest → middleware → HttpClient → fetch → backend

Proxy:   createProxyCaller("api") → caller.users.getAll() → POST /api/request → handler → executeRequest → middleware → HttpClient → fetch → backend
```

In direct mode, the caller invokes `executeRequest` directly with the `api` object. In proxy mode, the browser sends the request payload to your server's proxy route (e.g., `/api/request`), which then calls `executeRequest` on the server side.

## Setting Up Callers

### Direct mode — server-side <ModeBadge mode="direct" />

```ts title="lib/caller.ts"
import { createCaller } from "@noverax/courier"
import { api } from "@/api/sources"

export const caller = createCaller(api)
```

```ts
// Works anywhere with access to the api object
const users = await caller.users.getAll()
//    ^? User[]

const user = await caller.users.getById({ id: "1" })
//    ^? User
```

<Callout variant="info" title="When to use direct mode">
Use direct mode whenever you have access to the `api` object: Server Components, Server Actions, API routes, CLI scripts, cron jobs, or any non-browser runtime.
</Callout>

### Proxy mode — browser-side <ModeBadge mode="proxy" />

```ts title="lib/caller.ts"
import { createProxyCaller } from "@noverax/courier"
import type { api } from "@/api/sources"

export const caller = createProxyCaller<typeof api>()
```

```ts
// Browser sends POST /api/request → your server → backend
const users = await caller.users.getAll()
```

<Callout variant="tip" title="Type-only import">
Proxy mode imports `type { api }` — only the type information crosses to the client. The actual `api` object (with your backend URL and secrets) stays on the server.
</Callout>

## The Dot-Notation API

Both `createCaller` and `createProxyCaller` return a typed client with dot-notation access to your API groups and endpoints:

```ts
// Access endpoints via group.method notation
const users = await caller.users.getAll()
const user = await caller.users.getById({ id: "1" })
```

TypeScript validates group and method names at compile time:

```ts
caller.users.getAll()              // group: "users", method: "getAll"
caller.users.getById({ id: "1" }) // group: "users", method: "getById"
caller.posts.create(vars)         // group: "posts", method: "create"
```

## Call Options

Each endpoint supports runtime options that control how the request is executed:

```ts
// Raw response — returns { status, headers, data } instead of just data
const response = await caller.users.raw.getAll()
//    ^? { status: number; headers: Headers; data: User[] }

// Stream mode — returns raw Response object
const response = await caller.events.stream.stream()

// GET proxy — encodes as query params instead of POST body (cacheable)
const users = await caller.users.getAll(undefined, { method: "GET" })

// Upload with progress tracking
await caller.files.upload(formData, {
  onUploadProgress: ({ percent }) => console.log(`${Math.round(percent * 100)}%`),
})

// Abort signal
const controller = new AbortController()
await caller.users.getAll(undefined, { signal: controller.signal })

// Custom headers and timeout per call
await caller.users.getAll(undefined, {
  headers: { "X-Request-Id": crypto.randomUUID() },
  timeout: 5000,
})
```

### CallOptions Reference

| Option | Type | Description |
|--------|------|-------------|
| `rawData` | `boolean` | Return full `{ status, headers, data }` instead of just data |
| `stream` | `boolean` | Return raw `Response` for streaming |
| `method` | `"GET" \| "POST"` | Proxy HTTP method (GET for cacheable reads) |
| `signal` | `AbortSignal` | Cancel the request |
| `timeout` | `number` | Request timeout in ms |
| `headers` | `HeadersInit` | Additional headers for this call |
| `onUploadProgress` | `(progress) => void` | Upload progress callback (proxy mode, uses XHR) |
| `onDownloadProgress` | `(progress) => void` | Download progress callback |
| `forwardVariables` | `boolean` | Pass variables to the HTTP method (default: `true`) |

## Internal Lifecycle

When `executeRequest` receives a request payload, it goes through these steps:

1. **Resolve source** — looks up the source object in the `sources` map
2. **Resolve endpoint** — finds the group and endpoint function by parsing the `"group:method"` key
3. **Validate variables** — if the endpoint has a schema attached (via `.variables(schema)`), validates the input
4. **Run middleware chain** — executes middleware in array order, each wrapping the next
5. **Execute endpoint** — creates `HttpClient`, calls the endpoint function with `http` methods and variables
6. **Validate response** — if the endpoint has a response schema, validates the output
7. **Build response** — formats the result based on context (proxy Response vs direct data)

```
executeRequest
  ├─ resolve source & endpoint
  ├─ validate variables (if schema)
  ├─ middleware[0]
  │   └─ middleware[1]
  │       └─ middleware[n]
  │           └─ via(http, vars) → HttpClient.fetch → backend
  ├─ validate response (if schema)
  └─ return data (or Response for proxy)
```

## Context (Direct Mode)

In direct mode, you can pass an optional `Context` as the last argument to forward incoming request headers (useful in Server Components and API routes):

```ts
import { createCaller } from "@noverax/courier"
import { api } from "@/api/sources"

const caller = createCaller(api)

// In a Server Component or API route
const user = await caller.users.getById(
  { id: "1" },
  { req: request, headers: request.headers },
)
```

The context object accepts:

| Property | Type | Description |
|----------|------|-------------|
| `req` | `Request` | Incoming request (for header forwarding) |
| `res` | `Response` | When set, `executeRequest` returns a `Response` object |
| `headers` | `Headers` | Additional headers to merge |
