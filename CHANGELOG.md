## [0.5.0](https://github.com/NoveraX/courier/compare/v0.4.0...v0.5.0) (2026-11-13)

A call that got no answer now fails with an error of its own, and a retry policy repeats only what an upstream may get over, spaced and bounded. Realtime speaks protocol version 2 and reaches a user's connections on every replica; the proxy reads a request body as it arrives and holds it to limits; a record that holds a file goes as a form. `@noverax/courier/client` and `@noverax/courier/server` give a page and a server an entry each, TanStack Start has an adapter, and `@noverax/courier-docs` gives your editor's agent the docs of the release you install. `npx @noverax/courier-cli@latest upgrade` moves every `@noverax` package to 0.5.0 at once and carries over the code it can read for certain. Read the breaking changes below before you run it, and deploy the client and the server together: neither speaks the realtime protocol of 0.4, and a server of 0.4 refuses a record upload.

### Breaking changes

`npx @noverax/courier-cli@latest upgrade --dry-run` shows the plan. The upgrade rewrites what your code says for certain: the realtime errors' imports, `SSESubscription`, `sendAuthRequired()`, a `0` in `retryOn`, a check of status 0, `.via().reads()`, the string `PROXY_VARIABLE_NOT_SERIALIZABLE`, and each import of `@noverax/courier` to the entry of the side that loads its file. What it finds and cannot change, it names at its line with what to write instead.

- **A call fails with `NetworkError`, `TimeoutError` or Courier's `AbortError`.** A call that got no answer rejected with an `HTTPError` of status 0, a cancelled one with the platform's `AbortError`, and one a newer call superseded with status 499. An `HTTPError` now means an answer came. A `NetworkError` means none did, with the platform's code in `systemCode`; a `TimeoutError`, that the call's time ran out; Courier's `AbortError`, that it was cancelled, with the code `SUPERSEDED` where a newer call superseded it. `onError` is not told of a cancellation, and no retry repeats one. `onError` is typed with `RequestFailure`, `new HTTPError()` refuses a status outside 100 to 599 with a `RangeError`, and an answer the browser hides is `ConfigurationError` `RESPONSE_OPAQUE`.

  ```ts
  // 0.4
  if (isHTTPError(error) && error.status === 0) return showOffline()
  if (isHTTPError(error) && error.status === 499) return

  // 0.5
  if (isNetworkError(error) || isTimeoutError(error)) return showOffline()
  if (isAbortError(error) && error.code === "SUPERSEDED") return
  ```

- **A retry policy repeats what an upstream may get over, spaced and bounded.** Where `retryOn` says nothing, `retryMiddleware` and an endpoint's `.retry()` retry `408`, `425`, `429`, `500`, `502`, `503` and `504`, where they retried every 5xx and a timeout; a timeout is retried only where `retryOn` names `"timeout"`. A wait is random up to the doubling delay and never past `maxDelay`, 20 s, unless `jitter: "none"` asks for it exactly. A `Retry-After` is waited, and an answer that asks for longer than `maxDelay` is not retried. `limit` takes at most 10, and an API's calls share a retry budget. `retryOn` names `"network"` and `"timeout"` where it named `0`, and a function is handed the failure, not the response. An option the policy does not have is `ConfigurationError` `RETRY_OPTIONS_INVALID`, where it was ignored, and an endpoint's `.retry()` is checked on its first call.

  ```ts
  // 0.4
  retryMiddleware({ retryOn: [0, 503] })

  // 0.5
  retryMiddleware({ retryOn: ["network", "timeout", 503] })
  retryMiddleware({ retryOn: (failure) => failure.kind === "status" && failure.status === 503 })
  ```

- **The query hooks leave retries to Courier's policy.** `useQuery`, `useSuspenseQuery`, `useInfiniteQuery` and `useComputedQuery` retried a failed call three times; they no longer retry on their own. The endpoint's `.retry()` or the API's `retryMiddleware` repeats a call, or `defaultOptions.queries.retry` on your `QueryClient` keeps the hooks' retries.
- **Headers are checked before anything is sent.** A header value with a control character other than a tab, or with a character past U+00FF, is `ConfigurationError` `HEADER_VALUE_INVALID`, which names the header and not its value. The platform refused some of these with a `TypeError` that repeated the value, and Node's dispatcher others as an `HTTPError` of status 0, which was retried; see Security below. `authMiddleware` sends no `Authorization` header without a token, where it sent `Bearer undefined`, and with `required: true` refuses such a call with a `MissingTokenError`. An option it does not have, a `header` that is no header name or a `scheme` that is no scheme is `AUTH_OPTIONS_INVALID`. An `allowedHosts` entry with a scheme, a path or a user, which matched nothing, is `INVALID_ALLOWED_HOST` where the handler is made.
- **A server names its connections by a selector, and reaches them on every replica.** `connections` and `sseConnections` take a connection's id, `{ id }` with up to 1000 of them, or `{ meta }` comparing what `onConnect` returned, in place of a predicate. `disconnect()` returns a promise, as `connections.requireAuth()` does, and both act on every replica that shares the pub/sub adapter. `sendAuthRequired()` is gone: `connections.requireAuth()` asks for credentials again. A pub/sub adapter of your own implements `state`, `onStateChange()` and `stats()`, takes a subscription without waiting on its server, and queues what is published while it is not ready; the adapters Courier ships need nothing done. Handlers of one process that shared `createMemoryPubSub()` delivered nothing to each other: give them `createMemoryBus()`, each its own `bus.replica(name)`.

  ```ts
  // 0.4
  handler.connections.disconnectByMeta((meta) => meta.userId === userId, 4003, "Banned")
  sendAuthRequired(handler.connections, connectionId, 10_000)

  // 0.5
  await handler.connections.disconnect({ meta: { userId } }, { code: 4003, reason: "Banned" })
  await handler.connections.requireAuth(connectionId, { timeoutMs: 10_000 })
  ```

- **Every subscription is a `Subscription`, and a connection runs on one state machine.** `SSESubscription` is now `Subscription`, from `@noverax/courier/realtime`, which `WSChannel` extends. One written by hand needs `on()` for `data`, `error`, `status`, `open` and `close`, `reconnect()` and `dropped`; `on()` with an event it does not have is a type error, and `UNKNOWN_EVENT` as it runs. A connection is `connected` once the server admitted it, and a channel once the server confirmed its subscribe. A reconnect waits a random time up to the backoff's delay, which starts over once a connection stayed open 10 s. A page coming back reconnects at once unless `ws.reconnectOnResume` is `false`, and a `4401` asks for credentials anew. A stream reconnects by the same rules: a `retry:` field or a `Retry-After` is waited with the backoff's wait on top, never past five minutes, and `subscribeSSE` given a backoff no wait can be drawn from throws `INVALID_BACKOFF`.
- **The realtime errors come from `@noverax/courier/realtime`.** `AuthError`, `ForbiddenError`, `RateLimitError`, `fromErrorCode` and `isRealtimeError` moved there from the root. The realtime `TimeoutError` of 0.4, code 4408, is `RealtimeTimeoutError`: the root's `TimeoutError` is now a call's. `RealtimeError` and `ConnectionError` stay at the root, so a page that catches one need not load the realtime client.

  ```ts
  // 0.4
  import { AuthError, TimeoutError } from "@noverax/courier"

  // 0.5
  import { AuthError, RealtimeTimeoutError } from "@noverax/courier/realtime"
  ```

- **Realtime speaks protocol version 2: deploy the client and the server together.** Every socket's first frame is `auth` naming version 2, which the server answers with `auth_ok`, and neither side speaks the version before it. A page left from 0.4 on an upgraded server is refused with `1002`, which the 0.4 client does not retry; a client of 0.5 reconnects until the rollout has replaced a replica of 0.4. While the rollout runs, `connections.disconnect()` and `connections.requireAuth()` reach only the replicas already upgraded, so revoke the user's credentials as well. A connection given up for a newer one of its key is closed with `4409`, where it got `4429`; a stopping server sends `1001` in place of `1012`, and a slow consumer gets `1013` in place of `4008`. The client's `ws.heartbeat` and `ws.maxMessageSize` are gone: the server's settings hold, and `auth_ok` tells the client.
- **The proxy holds a request body to limits as it arrives.** A body shorter than its `Content-Length` is answered `413` `BODY_INCOMPLETE`, and a compressed one `415` `BODY_ENCODING_UNSUPPORTED`. One that sends no byte for 30 s (`bodyIdleTimeoutMs`), or takes 5 minutes in all (`bodyTimeoutMs`), is answered `408` `BODY_TIMEOUT`, and a JSON body that is not UTF-8, or a form that does not parse, `400` `BODY_MALFORMED`. A form is held to 1000 parts (`maxUploadParts`), to 8 KB of headers a part, and its text fields together to `maxBodyBytes`. Under Node, an upload's files past `uploadMemoryBytes`, 1 MB, go to disk in `uploadDirectory`, and `uploadMode: "memory"` keeps them in memory. Every upload together shares 64 MB of memory (`totalUploadMemoryBytes`) and 1 GB of disk (`totalUploadDiskBytes`): past that room an upload is answered `503` `UPLOAD_CAPACITY_REACHED` with `Retry-After`, and a disk with no room `507` `UPLOAD_STORAGE_FULL`. Under Node 22 and 24, an upload or a stream body is sent with `redirect: "error"`, so an upstream's redirect fails the call as a network error, unless the caller sets `redirect` itself. The mock reads a body with the server's own stream and parser, to the same limits.
- **A record that holds a file goes as a form, and what JSON cannot write is refused.** A direct call's record with a `Blob`, a `File` or bytes in a field is sent as a multipart form, each field a part, where it went as JSON with `{}` in the file's place. Through the proxy, which refused such a record, it goes as a record upload, `multipart/vnd.courier.variables`, which a server of 0.4 answers with `415`: deploy the client and the server together. A `Set`, a `Map`, a `BigInt`, or a file in a read's variables, is `ConfigurationError` `VARIABLE_NOT_ENCODABLE`, naming where it sits, before anything is sent. That code replaces `PROXY_VARIABLE_NOT_SERIALIZABLE`, from a direct call and a proxy call alike. A read's `FormData` sends its text fields in the address.
- **A `.via()` endpoint reads or writes as the verb its closure calls.** A closure that calls `http.get`, `head`, `options` or `query` was a write until `.reads()` said otherwise. It is a read now: retried, cacheable, taken by `useQuery`, and offered to an agent as a read; `.reads()` changes nothing. Name a GET that changes something a write with the new `.writes()`. A closure that calls a reading verb and a writing one is no endpoint until `.reads()` or `.writes()` names its kind. A call whose closure calls a verb of the other kind is `ConfigurationError` `ENDPOINT_VERB_KIND`. A closure typed `HttpProbe<Variables>` no longer says which verb it calls: leave its return type to be inferred, or name the kind.

  ```ts
  // 0.4
  endpoint.variables<{ q: string }>().via((http, v) => http.get("search", v)).reads()

  // 0.5
  endpoint.variables<{ q: string }>().via((http, v) => http.get("search", v))
  endpoint.get("unsubscribe").variables<{ token: string }>().writes()
  ```

- **A server checks the options only a server reads, and a page checks none of them.** `defineApi` refused, in every runtime, a `session`, a `forward` or a header list beside a session that could not work as written. Such options are now refused on every way a server calls the API with a request, whatever `NODE_ENV` says: as its sources are registered, as a handler or the server's caller is made, or on the first call it lends a request's session to. They are held as they were checked: `api.options` gives a frozen copy, and a later change reaches no call. A page's definitions carry none of these checks. A page or an app refuses only a call that would carry its session over plain HTTP across the public internet. `.agent()` given what it does not take is `AGENT_OPTIONS_INVALID` as the sources are registered, and as `courier-mcp` lists its tools. `createCaller` from the root is the server's caller under Vitest with jsdom, and in an Electron renderer that loads Courier as Node does: a test of a page's calls takes it from `@noverax/courier/client`.
- **`create-courier` needs Node.js 22.13, and `--yes` stops at changes git has not committed.** Studio and its mock need Node.js 22.13 or later, and `create-courier` refuses an older one as it starts. `create-courier --yes` and `courier-cli setup --yes` change nothing in a project whose changes git has not committed, unless `--allow-dirty` is passed. `--no-studio` leaves the example's mock out too, as Studio runs it, and `--mocks` beside `--no-studio`, `--openapi` or `--no-example` is refused.
- **Studio imports a specification by new rules.** A specification that holds a file's bytes, as `format: binary` or OpenAPI 3.1's `contentMediaType`, is hashed anew. **Manage** shows its import as changed once, and a URL import's `pinHash` is refused with `409` `SPEC_PIN_MISMATCH`: import it again, then pin the new hash. An address with a user or a password is refused with `400` `SPEC_CREDENTIALS_IN_URL` before anything is sent. One with a secret parameter, `?api_key=` say, is not declared in `courier.config.ts`, but left to you with `SECRET_IN_FROM` and the lines to add. Give such credentials as the import's `auth`. A multipart operation, once imported again, takes a record of its fields, `{ file, note: "hi" }`, where it took a `FormData`.
- **Courier File Icons go in as the editor starts.** The icons go into Material Icon Theme or vscode-icons in any workspace, where 0.4 asked first in a Courier project, and one message says so, with **Take Them Out**. `courier.fileIcons.offer` is now `courier.fileIcons.automatic`, read from your user settings alone, and the extension carries your answers to 0.4 over as it starts.

### Security

- **A token's refresh goes only to the calls refused with the token it renews.** `authMiddleware` kept one refresh for the API, and handed its token to any call refused while it ran. On a server, where `getToken` and `refreshToken` read the user of the request being served, a call of one user refused with `401` during another user's refresh was sent again with that user's token, and answered as that user. A refresh is now shared by the token it renews: a call joins it only when it was refused with the token that refresh replaces. A hundred calls of one user refused with its expired token still cost one refresh.
- **An agent's call carries nothing of the request it came on.** The MCP endpoint is served as one of your server's requests, which the request context of Next.js or of an adapter holds while it is served, and a tool's call took that request's session: the agent's cookie, a bearer read from it and the headers the API forwards went upstream with it, though the MCP server promises that none does. A tool's call is now the server's own, made for the agent: no session, forward or address chain reaches the API, and no newer call cancels it.
- **A server with a DOM on its global object keeps each user's calls apart.** A read that cancels the previous call did so wherever the global object held a `document`, the sign of a browser. On a server that put a DOM there for a library, one user's call cancelled another user's still in flight, and a call took its session from that DOM's cookies. A call is now held for a newer one to cancel only where it is one user's own: in a page or an app, with no request being served. The server's caller takes no session from a DOM on the global object.
- **A socket whose renewed credentials are refused is closed at once.** Credentials a client sent again that `onReauth` refused were answered with an error frame. The connection went on as the user it was admitted as until the deadline `sendAuthRequired` set, and for good where it set none or the client sent them unasked; a handler with no `onReauth` did the same. Renewed credentials that changed who the connection was kept its subscriptions as they were. Such credentials now close the connection with `4401`. Where renewed credentials change who the connection is, each of its subscriptions is authorized again, and one the new identity may not hold ends with `4403`.
- **Studio sends a page without the project's token only what an export would carry.** Studio cut the live view of a page opened without the project's token, but sent other things whole: the requests replayed to each page as it connected, a mock's log, and the drafts of the other pages. Its cut covered the headers, the addresses and the error texts alone, never the variables or the answers. A visitor of a public demo, reloading the page, was sent what other visitors had sent before, passwords and tokens among them. Every message to such a page now goes through one place, which sends an event only as an export carries it, each value cut by the core's rules, and sends nothing it does not name.
- **Studio writes no credential from an import's address into your project.** An import's address with a user and a password was written into `courier.config.ts` as given, as the import's `from`, and so was one with a secret parameter, so the key went into the repository. Studio now refuses the first before anything is sent, and leaves the second to you with the lines to add, the secret read from an environment variable; see Breaking changes above.
- **The VS Code extension runs Studio's commands with no shell reading their words.** **Import an API** and **Check API Changes** typed their command into the terminal's shell, each word quoted for it. On Windows that shell is PowerShell, which reads some characters inside double quotes as its own, so a pasted address could run a command, and cmd read others through npx's `.cmd` file. The terminal now starts the command itself with its words whole, so no line is typed into a shell, and none stays in its history.
- **Studio's snippets write each value as code reads it.** A stream's cURL and websocat commands put its address and headers between single quotes without escaping a quote in them, and the HTTP cURL wrote the method as a bare word. The browser snippets wrote an address and an event's name between double quotes as they were. So a quote in what a recorded request carried ended the string, and what followed it ran as the shell's code or the page's. Each value is now one word of the shell, a JavaScript string literal or JSON written as code, and websocat is given the address as a socket's URL.
- **A visitor's long `X-Forwarded-For` keeps the proxies' part of the chain.** A chain over 512 characters, or holding a character no address has, was dropped whole, and the hops the proxies in front had appended went with it. A user who sent one made Courier name the balancer as the user, or send no chain at all, and an upstream counted the user by the balancer's address. The chain is now read from the right, where the proxies wrote it: the nearest eight hops at most, up to the first that is no address.
- **Courier's settings are read from the environment's own variables.** Node reads a variable its environment does not have from `Object.prototype`, where other code in the process may have put one, and the core read its settings so. `COURIER_TRUSTED_PROXIES` found there made the proxy believe the address a visitor wrote in `X-Forwarded-For`, past the rate limit, and `NODE_ENV` opened its check of the host. Each variable is now taken only where the environment has it of its own, and a mode that only the prototype holds keeps every check closed.
- **A header value with a line break is refused before the platform repeats it.** The platform refused a header value with a NUL or a line break with an error that repeats the value whole, so a token read from a file with a stray line break went into whatever logged or showed the error. Courier now refuses it first, with `HEADER_VALUE_INVALID`, naming the header and not its value.
- **The server's log, Studio and the MCP server cut more credentials.** The server's log printed each line and the error under it as they were. Studio's cut, which the MCP server's error texts went through as well, kept a password written after a label, a credential named in prose, and a signature, a one-time password or a session id under a short name. `redact()`, from the root and `@noverax/courier/server`, now cuts every credential out of a text, headers, an error with its causes, or data of any shape. The server's log, Studio's exports, session files and tools for agents, and the MCP server all cut by its rules.

### Realtime

- **A user's connections, on every replica.** `connections.disconnect()` and `connections.requireAuth()` act on the connections a selector names wherever the load balancer sent them, through a command on the pub/sub adapter, and `sseConnections.disconnect()` ends a user's streams on every replica the same way. `connections.list()` lists this replica's. See [A User's Connections, on Every Replica](https://courier.noverax.cloud/docs/deployment/replication#a-users-connections-on-every-replica).
- **Commands between replicas are signed.** Give every replica the same `cluster: { secret }`, of 32 bytes or more, and each command is signed with HMAC-SHA-256. One not signed with the secret, sent again, or sent more than a minute ago is refused, each on one line of the server's log; a shorter secret throws `CLUSTER_SECRET_INVALID`. Without a secret the commands are taken unsigned, and the log says so once for each adapter. See [Signing the commands](https://courier.noverax.cloud/docs/deployment/replication#signing-the-commands).
- **A user's connections are capped across replicas.** `maxConnectionsPerKey: { key, max, onExceed }`, or a list of such rules, limits the connections that share a key, read from what `onConnect` returned or from the connection's address. They are counted in `connectionLeases`, which `createRedisConnectionLeases()` keeps in Redis for every replica. Over the limit, the oldest connection of the key is closed with `4409`, or, with `onExceed: "reject"`, the new one with `4429`. A store that does not decide within 2 seconds leaves the decision to the replica's own count. See [Capping a User's Connections](https://courier.noverax.cloud/docs/deployment/replication#capping-a-users-connections).
- **A subscription resumes from the events it missed.** With the handler's `history`, a client that comes back to the replica it left is sent what was published on its topic meanwhile, before `onJoin` runs, which reads `ctx.recovered`. A position the history no longer reaches starts over from `onJoin`. A pub/sub adapter with a log, `createRedisPubSub({ publisher, subscriber, log: {} })` or `createMemoryBus({ log: {} })`, numbers each topic's events on one sequence, so a subscription resumes on any replica. See [Resuming Subscriptions](https://courier.noverax.cloud/docs/deployment/replication#resuming-subscriptions).
- **Pub/sub rides out an outage of Redis.** The Redis pub/sub adapter listens from the moment it is made, makes each subscription again after every reconnect, and queues what is published while Redis is away, within bounds of count, bytes and age; `disconnect()` settles within its deadline. Once it is back, each subscription is told `resync`, or caught up from the log where the adapter keeps one.
- **A handler hands back its connections and its stop.** What `courierWSAttach` and the Fastify and Hono `courierWSHandler` return carries the handler's `connections`, `destroy({ timeoutMs })` and `stats()`, so an application on them can reach its connections and stop the handler. `createWSHandler()` and `createCourierServer()` have `stats()` too.
- **The React hooks reconnect.** `useSubscription` and `useChannel` return `reconnect` beside `status` and `error`. It reconnects at once, opens again a stream or a channel its server ended or refused, and clears `error`.

### Calls

- **`.safe()` calls an endpoint without throwing.** Every HTTP endpoint's method has `.safe()`, which resolves to `{ data, error: null }` or to `{ data: null, error }`. The `error` is a `CallFailure`: an `HTTPError`, a `NetworkError`, a `TimeoutError`, a `ValidationError` or a `MissingTokenError`, which `isCallFailure()` tells apart in a `catch`. A cancelled call and a `ConfigurationError` still reject. See [Calling Without Throwing](https://courier.noverax.cloud/docs/api/call-errors#calling-without-throwing).
- **`.map()` maps an answer once its schema has checked it.** Each stage is handed the data with the answer's `status` and `headers`, the stages run in the order they are named, an asynchronous one too, and the call is typed with what the last one gives. A browser's call through the proxy runs them on the server, so the page gets only what they gave. See [Mapping the answer](https://courier.noverax.cloud/docs/core-concepts/defining-apis#mapping-the-answer).
- **`.writes()` makes a read-shaped endpoint a write.** A GET that changes something, such as an unsubscribe link, is sent once per call, its answer never kept, carried by the proxy as a POST, and offered to no agent as a read; the upstream still gets a GET.
- **`multipartBody()` sends fields as a form.** From `@noverax/courier/define`, it writes a closure's fields as `multipart/form-data` whether a file is among them or not, for an API that takes nothing else. A `FormData`, or an upload the proxy sends on as it arrives, is passed on as it is.
- **`redact()` cuts the credentials out of what you log or send elsewhere.** It takes a text, headers, an error or data of any shape, and returns the value itself where there was nothing to cut. See [redact()](https://courier.noverax.cloud/docs/api/redact).

### The proxy

- **An upload can go on as it arrives.** With `uploadMode: "stream"` the proxy keeps nothing of an upload. The call's variables are a `StreamedUpload`, which `isStreamedUpload()` from `@noverax/courier/server` tells apart, and the form goes to your backend as the backend reads it. Such a call is not retried, as its body cannot be sent twice. See [Sending an upload on as it arrives](https://courier.noverax.cloud/docs/proxy-mode/uploads#sending-an-upload-on-as-it-arrives).
- **`courier-server` reads the upload options from the config.** Its server block takes `uploadMode`, `uploadMemoryBytes`, `totalUploadMemoryBytes`, `totalUploadDiskBytes`, `uploadDirectory`, `maxUploadParts`, `bodyIdleTimeoutMs` and `bodyTimeoutMs`.
- **`allowedHosts` and `allowedOrigins` can be read where the app runs.** Each takes a function, called on the first request and remembered, so a list computed from a variable only the running app has no longer fails the build. Without a list, or an answer from the function, they are read from `COURIER_ALLOWED_HOSTS` and `COURIER_ALLOWED_ORIGINS`, comma-separated; the config wins over the environment.

### The client and the server entries

- **A page and a server each have an entry.** `@noverax/courier/client` offers what a page calls with: the callers, the errors a call fails with, middleware and the helpers a page uses. `@noverax/courier/server` offers what a server takes: the handlers, its caller, the double-submit token and what an adapter registers. `@noverax/courier` keeps every name it had. See [createCaller](https://courier.noverax.cloud/docs/api/create-caller#import).
- **The server's caller is refused on a page's modules.** Where the core's modules are a page's, as in Jest's jsdom environment or under Node's `--conditions=browser`, `createCaller` from `@noverax/courier/server` throws `ConfigurationError` `SERVER_CAPABILITY_MISSING` as it is made, rather than carry the page's session.
- **A page loads less.** The definitions a page imports no longer reach the HTTP client, a proxy caller's page leaves out what only a direct call reads, and the realtime errors, an upload's progress reporting and how Node prints an `HTTPError` load only where they are used.

### Frameworks and build

- **TanStack Start.** The new `@noverax/courier-tanstack-start` serves the proxy from two server routes, `apiRoute()` and `sseRoute()`, for React and for Solid. `createServerCaller` from its `/react` or `/solid` entry carries the user's session in server functions, loaders and routes, `requestContext()` lends it to the calls made while the server renders a page, and `csrfTokenMiddleware()` hands a page its double-submit token. Both entries carry TanStack Start's `server-only` marker. Courier's plugin is `/plugin` under Vite and `/rsbuild` under Rsbuild, and `npx @noverax/create-courier` sets it all up. See [TanStack Start](https://courier.noverax.cloud/docs/frameworks/tanstack-start).
- **A project's config says why it did not load.** Every tool that reads `courier.config.*` fails with `ConfigLoadError`, whose code is `MODULE_NOT_FOUND`, `MODULE_REFUSED`, `TRANSFORM_FAILED`, `EVALUATION_FAILED` or `LOAD_TIMED_OUT`. It names the module that failed and the chain of imports from the config to it, gives a hint, and quotes the project's message with its secrets cut. See [When the project does not load](https://courier.noverax.cloud/docs/reading-your-project#when-the-project-does-not-load).
- **A framework's own modules are answered as its server answers them.** `server-only` is an empty module and `client-only` is refused, and SvelteKit's `$env/*` and `$app/environment` and Astro's `astro:env/*` read the environment. `courier-cli routes`, Studio, the mocks and the routes plugin now read a project whose API modules import them. See [Modules your framework answers itself](https://courier.noverax.cloud/docs/reading-your-project#modules-your-framework-answers-itself).

## [0.4.0](https://github.com/NoveraX/courier/compare/v0.3.1...v0.4.0) (2026-11-04)

A page's proxy client now takes its routes from `@noverax/courier/routes`, which Courier's plugin for your build builds from `courier.config.ts` as it bundles the page: no routes file to write, commit or keep in step with the marks. There is a plugin for Next.js, Nuxt, SvelteKit, React Router, Remix, SolidStart and Astro, for Vite, webpack, Rspack, Rsbuild, esbuild, Rollup, Rolldown, Parcel, Metro and Angular's builders, and for Vitest and Jest; `courier.routes.ts` stays for every build without one. `cancelPrevious` is on or off wherever a call is configured, the types know which endpoints a page may call, and a path writes `{name}`, `{+name}` and a colon it sends as written. Install 0.4.0 of every `@noverax` package at once, and read the breaking changes below before you do.

### Breaking changes

- **`cancelPrevious` is `true` or `false`.** It named the reads a newer call cancels, as a list of paths on the API. It is now on or off on a call's `.with()`, an endpoint's `.cancelPrevious()`, a group, a client and the API, the nearest that says deciding, and off where none does. An API, a group or a client given a list throws `CANCEL_PREVIOUS_INVALID`, and so does a proxy client given routes that carry one; a call given one rejects with it. Mark those reads instead, and write `courier.routes.ts` again with `courier-cli routes` if you keep it. See [Where to turn it on](https://courier.noverax.cloud/docs/advanced/abort#where-to-turn-it-on).

  ```ts
  // 0.3
  export const api = defineApi({ baseURL, cancelPrevious: ["users.search"], groups: { users } })

  // 0.4
  const users = defineGroup({
    prefix: "users",
    endpoints: { search: endpoint.get("search").variables<{ q: string }>().cancelPrevious() },
  })
  export const api = defineApi({ baseURL, groups: { users } })
  ```

- **`defineGroup` and `defineApi` take the expose mark as a type argument.** The mark now moves the types, so a call that passes its type arguments explicitly together with `expose` passes the mark too, after its others: `defineGroup<Endpoints, true>({ expose: true, endpoints })`. `NeutralMethods` no longer declares `expose`; each builder does.
- **`@noverax/courier-studio-core/config` is gone.** The config loader and its transform cache are `@noverax/courier-build/config`, a package that needs nothing of Studio's runtime, and `findMocksFile`, `MOCKS_BASENAMES`, `loadCourierMocksFile` and `readMocksExport` are `@noverax/courier-studio-core/mocks`. `courier-cli` and `courier-server` no longer install Studio's runtime.
- **A config is looked for up to the top of the project, and one above your folder must be yours.** Every tool that reads `courier.config.*` stops at the folder that holds the project's repository (`.git`, `.hg`, `.jj`) or is the root of its workspace, where it climbed to the root of the file system. A config found above the folder the search starts from runs only when it belongs to you or to that folder's owner and no user outside its group may write it; any other is refused with `UntrustedConfigError`, code `CONFIG_NOT_TRUSTED`. See Security below.
- **`{name}` in a path is a parameter, and a path may not write a fragment.** Braces around a name were sent as text; they now mark a parameter, which the call fills. Braces around anything else are sent as before. A path that writes a `#` is refused where it is declared, with `PATH_FRAGMENT`: what follows it never reached the server, and a read's query went after it, where the request dropped it.

### Routes the plugin builds in

- **`@noverax/courier/routes` gives a page the routes of every source.** Register your config once, as a type, and `createProxyCaller(routes.shop)` reaches what the marks open of the source your config names `shop`, typed from it. Without the plugin the module throws `ConfigurationError` `ROUTES_NOT_BUILT` where a page first takes its routes, naming the plugin your build needs, and never falls back to the definitions. `createProxyCaller` and `createProxyQueryCaller` refuse anything but one API's routes with `ROUTES_INVALID`. See [The routes](https://courier.noverax.cloud/docs/proxy-mode/expose#the-routes).
- **A plugin for your build.** `withCourier(nextConfig)` from `@noverax/courier-next/plugin` builds them under Turbopack and webpack, in Next.js 14, 15 and 16; `courierRoutesModule` from `@noverax/courier-nuxt/plugin` under Nuxt's Vite, webpack and Rspack builders; `courierRoutes()` from the `/plugin` of `@noverax/courier-sveltekit`, `@noverax/courier-remix` (React Router and Remix) and `@noverax/courier-solid` in a Vite config; and `courierRoutesIntegration()` from `@noverax/courier-astro/plugin`. The new `@noverax/courier-build` has the plugins for Vite and Vitest, webpack, Rspack, Rsbuild, esbuild, Rollup, Rolldown, and Metro under Expo or React Native's CLI, and a transformer for Jest. Angular 20, 21 and 22 build them with the builders of the new `@noverax/courier-angular`, and Parcel with the new `@noverax/parcel-transformer-courier`. Each needs `@noverax/courier-build` beside it: a dev dependency, or a dependency in a Next.js app, whose `next start` loads `next.config`. See [The plugin for your build](https://courier.noverax.cloud/docs/proxy-mode/expose#the-plugin-for-your-build).
- **The routes follow your edits.** The plugin reads the config in a process of its own, never in your bundler's, and again only once something it depended on has changed: a module it imports, a file it reads, a folder it lists, a variable it looks at — under Vite with the values of the mode's env files that Vite gives the app. A dev server serves the new routes after an edit without a restart, and while the config fails it keeps the routes it read last and says why; a production build fails with what the config threw. A config saved where none was, above Vite's root as a Nuxt 4 app keeps it too, is read as it appears, and under Vitest an edit reruns the tests that import the routes with the new ones.
- **No definition ships with a page by accident.** A page's bundle that imports `courier.config.ts` as a value fails the build under every plugin: it would ship your server's settings and every API's definition to the browser.
- **New projects take the plugin, and `courier-cli setup` moves yours to it.** `npx @noverax/create-courier` sets up a Next.js, Nuxt, SvelteKit, Astro, React Router, Remix or SolidStart app with the plugin, and keeps Studio from writing `courier.routes.ts`, which no page would import; `--routes file` writes the module as before, and Express, Hono, Fastify and NestJS servers take it. `npx @noverax/courier-cli setup` moves a project from `courier.routes.ts` to the plugin: the plugin in the build's config, each module that imports the routes module reading `routes.<source>` instead, `studio.routes` set to `false`, the package installed. `--dry-run` shows the plan, `--yes` makes the changes without asking, and `--no-install` names the install command; a module that takes the routes module whole, or passes it on, is left to you with the lines to write. Studio's import writes a proxy caller that takes the plugin's routes where your config keeps no routes module.

### Security

- **`.expose()` handed `undefined` keeps the endpoint the server's.** `.expose(open)` opens an endpoint for `true` alone, but its default parameter took an explicit `undefined` for no argument at all, so `.expose(settings.searchPublic)`, with the flag left out of a deployment's settings, opened the endpoint to every page. Named alone, `.expose()` still opens it; handed a value, only `true` does.
- **Only your own config runs.** Studio, its runtime, `courier-cli`, the standalone and MCP servers, and now the plugins run the `courier.config.*` they find. The search climbed to the root of the file system, so a config another user put in a shared folder such as `/tmp` ran with the rights of whoever worked in a project below it. It now stops at the top of the project, and a config found above the folder it starts from runs only when it belongs to you or to that folder's owner and no user outside its group may write it.
- **A proxy client on a server cancels nothing.** A page rendered on the server reaches its proxy in process, so with `cancelPrevious` on, one user's search could cancel another's. A proxy client now cancels calls only in a browser page or a React Native app, as a direct client does.
- **An agent is told why a call failed, without an address's credentials.** Courier's MCP server told an agent only "fetch failed" for a call that failed in your own code on the way, and the platform's words without their code for one that got no answer — words that could carry an address's credentials and query. Each network failure in the chain of causes is now told with its code, every address cut to its scheme, host and port, and every credential cut by the rules Studio cuts error texts by; a cause of any other origin is left out. Those rules now also cut an address `fetch` quotes as it refuses one, and a password that a quote, a space or a bracket splits, which Studio's own cut let through whole.

### Defining APIs

- **The types know which endpoints a page may call.** `.expose()` moves an endpoint's type wherever the chain names it, before the HTTP verb as well as after it, and `defineGroup` and `defineApi` keep their `expose` as written. `ExposedPaths` reads them by the rule the proxy applies — the endpoint's own mark, then the nearest group's, then the API's — and `ExposedRoutes` types the routes built from a definition, so a client given them reaches exactly what the proxy serves. A flag known only at run time may open an endpoint, so the types let a client name it, and the routes decide. `endpoint.expose().get("search")`, which compiled and threw, now works.
- **A path writes `{name}`, `{+name}` and a colon it sends as written.** `files/{id}abc` ends the parameter's name where text follows it at once; `{+name}` sends its value with its slashes, each part encoded, as Google's `v1/{+name}` takes `projects/p/operations/o`; and `::` is one colon the path sends as written, so `index::inspect` is requested as `index:inspect` and `:name::cancel` as `op-1:cancel`. A value that makes a part empty, `.` or `..` is refused. The types read each form as the request does, the OpenAPI document writes them as `{name}`, and a call to an absolute URL reads its path the same way, its query kept. See [Path parameters](https://courier.noverax.cloud/docs/advanced/path-params#a-value-with-slashes).
- **`http.path` puts a value into a closure's path.** A closure that interpolated its variables into a path handed the request a string it then read as a path: `report:draft` became a parameter, `::` became one colon, and a `?` or `#` started a query or a fragment. ``http.path`files/${name}` `` sends each value as text, encoded, and reads the text around it as any path; a call refuses a value that is `undefined` or `null`, one no URL can hold, and one that leaves its segment empty, `.` or `..`. See [A value in a closure's path](https://courier.noverax.cloud/docs/advanced/path-params#a-value-in-a-closures-path).
- **A path's own query is text.** A `:name` in a query the path writes was read as a parameter: `http.get("items?sort=:field", vars)` took `field` out of the call and filled nothing with it, and a stream at `:room/events?since=:start` refused to open without a `start`. A path is now read up to its first `?`; what follows is sent as written, and a read's variables go to the query string beside it.
- **A name no endpoint may take is reported at the name.** An endpoint named `options`, `raw` or `with` in a group, or in a source's own endpoints or groups, was reported on the whole `defineGroup(` or `defineApi(` call; the error now marks the name and says what it is kept for. An endpoint named `__proto__` vanished from its source or group, with the types satisfied, and its members became the source's own: it now throws `RESERVED_ENDPOINT_NAME` where it is defined. A group of that name, which a client reaches like any other, stays.
- **Groups keep their types.** A group of groups written in place in `defineApi`'s `groups` was typed `never`, and so was a group a library's generic factory returned, in the library's declaration file. Both are typed as they are written now, and `createProxyCaller`, `createProxyQueryCaller` and `createProxyQueryKeys` take routes typed by `RouteMap` under `exactOptionalPropertyTypes`.

### Calls

- **`cancelPrevious` reaches a call wherever it waits.** An older call still getting ready to send, or waiting between the attempts of its retry policy, was out of a newer call's reach, and when it sent at last it cancelled the newer one: the stale answer won. A call now holds its endpoint from the moment it starts until it settles, and a newer call cancels one with no request in flight at once. Only calls it is on for take part, so a call made with `false` always completes, and a write is never cancelled: `.cancelPrevious()` on an endpoint that writes is a type error, and throws `CANCEL_PREVIOUS_ON_WRITE` where it is written. Every proxy client given the same routes shares the calls in flight, as every direct client of one API does.
- **A superseded call is reported as cancelled.** `retryMiddleware` answered a call cancelled just after an attempt failed with that attempt's failure; it now answers with the cancellation. React Query's hooks never retry a query whose call a newer one cancelled, or whose own signal aborted: TanStack Query sent such a read again, and two components reading one endpoint went on cancelling each other. Any other failure is retried as the hook, its client or React Query say.
- **A page Nuxt renders with webpack or Rspack calls with the user's session.** Those builders bundle a page's own copy of Courier beside the copy Nitro's plugins load, and the proxy, which the other copy runs, never found the mark a rendering page's in-process call carried: the API got the call without the user's cookies. The mark, and what the calls made for one request share, now live on the global object under `Symbol.for` keys.
- **A page loads less.** A page with React Query hooks no longer loads the server's code at start, and a proxy caller's page no longer loads the path reader, which only a direct call runs.

### Mock servers

- **Paths are served as the client sends them.** A segment that holds a parameter beside text, as `:from-:to` or Google's `:name::cancel`, is routed whole and its parameters split out of the value; `{name}` and `{+name}` are served, a `{+name}` taking the segments its value spans, after the routes that take one segment, as Google's list `{+parent}/services` sits beside its get `{+name}`; and a stream or a channel whose path writes a query is served at the path before it, as an HTTP endpoint is. Streams and channels are tried in the order HTTP endpoints are, a fixed segment before a parameter and a parameter before a `{+name}`, where they went in the order they were declared.
- **A mock moves past a port the system keeps for itself.** Windows keeps blocks of ports for Hyper-V, WSL and Docker and refuses a bind there with `EACCES`, so a mock that looks for a free port stopped there with that error. It now moves past such a port, from 1024 up, as it does past a taken one.

### Agents

A `{+name}` now says that it may hold slashes, which are sent as written, so an agent no longer encodes a resource name into one segment.

### Studio

The raw view numbers lines past 9,999 in a column wide enough for them.

The Playground shows, fills and copies `{name}` and `{+name}` as the call sends them, a `{+name}`'s slashes kept, and a path's own query beside a read's query; a cURL or fetch snippet copies a base URL's colons as written.
- **Why a request got no answer, wherever it is listed.** The line the editor lists, its failure notices, its chat and Studio's agent tools now carry the system's reason and code, not "fetch failed" alone. A failure of your own code that a request it made caused — a token fetched in a middleware, a lookup in `pathOptions` — is now traced to that request through the errors your code wraps it in, and gets the advice its code calls for, about the host that code called. A certificate not trusted is advised on for more of OpenSSL's verdicts, naming `NODE_USE_SYSTEM_CA=1` beside `NODE_EXTRA_CA_CERTS`.
- **A page shows what is so while it loads.** No app attached, waiting for requests, empty reports, OFFLINE and REC no longer flash while a page connects; each waits for Studio's word, and the APIs page, cut off from Studio, keeps what it had and says so. A saved session is sent in place of the live requests, Back to live keeps their pins and shows them loading, clearing the saved sessions sends them, and the banner Opened from a session file is kept to sessions opened from a file. Every empty state sits in the middle of its space, each Mocks tab says why it is empty without a mock server, and an unknown address reads Not found in the header.
- **The Playground's editor.** A quote shows the moment it is typed; Tab, Shift+Tab and ⌘/ join the undo history; ⌘/ keeps the selection on its lines, leaves out a line the selection only reaches the start of, and leaves blank lines as they are; and a focus moved as a menu or a dialog closes stays where it went.
- **A SolidStart 2 page connects to Studio.** SolidStart 2 leaves `browser` out of its client's resolve conditions, so a page got the runtime's server build, which threw as it attached, and the error overlay covered the page. The Vite plugin now gives every page the runtime's browser build, with Vite 5 to 8, and the server build attaches in a page as well.

## [0.3.0](https://github.com/NoveraX/courier/compare/v0.2.0...v0.3.0) (2026-10-14)

The proxy now serves only the endpoints you mark, and a page's client takes the routes Courier writes from those marks instead of a boundary declared beside them — Studio as it runs, and the new `courier-cli` in CI or wherever Studio does not run. Studio's search finds what a large answer's shown part leaves out, Studio reads your `.env` files again when you save one, and a page loads less of Courier at start.

### Breaking changes

- **The proxy serves only what you mark.** An endpoint is reachable from a page only where a mark opens it: `.expose()` on the endpoint, or `expose` on its group or its API, the nearest one deciding. Before, the proxy served every endpoint nothing shut, so an endpoint written for a cron job or an admin tool was a page's to call, with your server's credentials, until someone remembered it. An API that marks nothing is now reachable from no page; `expose: true` on it opens all of it, as before. A refused call is answered exactly as a name the API does not define, and while you develop the server's log names the endpoint and the fix, once. See [Exposing Endpoints](https://courier.noverax.cloud/docs/proxy-mode/expose).
- **`defineBoundary` is removed: a page's client takes its routes.** The marks are the one place that says what a page may call. From them Courier writes `courier.routes.ts` beside your `courier.config.ts` — each endpoint a page may call and how it reaches it, typed from your API and holding nothing of its definition: Studio whenever it loads the config, and `courier-cli routes` without Studio. `createProxyCaller`, `createProxyQueryCaller` and `createProxyQueryKeys` take those routes in place of a source's name and its boundary:

  ```ts
  // 0.2
  export const boundary = defineBoundary({ source: "api", expose: { "users.list": "query" } })
  export const api = defineApi({ baseURL, boundary, groups: { users } })
  const client = createProxyCaller<typeof api>("api", { boundary, proxyPath })

  // 0.3
  const users = defineGroup({ prefix: "users", expose: true, endpoints: { list } })
  export const api = defineApi({ baseURL, groups: { users } })
  const client = createProxyCaller(apiRoutes, { proxyPath }) // from "./courier.routes"
  ```

  Commit the module with the marks, and review it as you review a permission: a `CODEOWNERS` line gives it the owners of the API. `npx @noverax/courier-cli routes --check` writes nothing and fails a CI step when it is out of date. A project without a `courier.config.ts` writes its routes by hand, held to the API by `RouteMap`. A client asked for an endpoint its routes do not name throws `ENDPOINT_NOT_IN_ROUTES` before anything is sent. `BOUNDARY_MISMATCH`, `BOUNDARY_SOURCE_MISMATCH` and `ENDPOINT_NOT_IN_BOUNDARY` are gone with the boundary, and `ProxyCallerDefaults` and `ProxyCallerArguments` are no longer exported; `ProxyCallerOptions` is. See [createProxyCaller](https://courier.noverax.cloud/docs/api/create-proxy-caller).
- **A page's client takes its `proxyPath` from its own options.** A `proxyPath` on `defineApi` no longer reaches it, since the routes carry nothing of the definition; it tells Studio's Playground where your proxy routes are. A client given none sends to `/api/request` and `/api/sse` on the page's origin, as before.
- **A read goes to the proxy as GET only where it declares `.cache()`.** Its variables then travel in the address, so a browser and a CDN may keep the answer its `.cache()` allows. Every other read goes as POST, as a write does, its variables kept out of every log between the page and your server. A call can still ask for either verb with `.with({ method })`.
- **An API Studio 0.2 imported with a proxy caller** has no mark, and its `proxy.ts` names the source in the 0.2 form. Studio writes both in the new form the next time it writes the import — `expose: true` on the API in `source.ts`, and the caller taking the routes in `proxy.ts`; until then, make those two changes by hand. See [Import an API](https://courier.noverax.cloud/docs/studio/import-api).

### CLI

- **`@noverax/courier-cli` is new: the routes without Studio.** `courier-cli routes` writes `courier.routes.ts` in a project that does not run Studio, in a script or in CI, with the code Studio writes it with, so the two write the same bytes; `--check` writes nothing and fails when the module is out of date. Install it in the project, so CI runs the version your lockfile pins. See [Exposing Endpoints](https://courier.noverax.cloud/docs/proxy-mode/expose).

### Studio

- **Studio writes the routes a page's client takes.** It writes `courier.routes.ts` as it loads the config, formatted as your project's code is, only when the module would change, and never over a file Courier did not write. `studio.routes` in `courier.config.ts` puts it elsewhere, or `false` keeps the project without one. See [defineConfig](https://courier.noverax.cloud/docs/api/config).
- **The Explorer shows which mark lets a page call each endpoint.** An endpoint a page may call is tagged `exposed`, and its definition names the mark that decided — `expose: true on users`, `marked .expose(false)`, `nothing marks it .expose()`. In proxy mode the Playground flags an endpoint no mark opens `not exposed`, and refuses to send it, saying where to open it.
- **Run an endpoint kept to the server as server code.** The Playground's `not exposed` chip opens on why the proxy refuses the endpoint, and **Run as server code** switches to Direct mode and sends the call there, on the app's runtime, as your server code does. The Explorer's Pages row opens the Playground in Direct mode on such an endpoint and sends nothing until you do. The proxy still refuses a page's call, so no endpoint has to be opened to be tested.
- **Find searches the whole of a large answer.** An answer or a body over 16 KB shows in part, and Find used to search only that part. It now searches the whole body, which the app or the mock keeps, in a worker of its own, so the page stays responsive. Matches in the parts left out show in the tree and in the raw text, with the lines numbered as in the whole body, and the line under the field says how much was found. Once the whole is no longer kept, Find searches the part shown and says why. See [Studio](https://courier.noverax.cloud/docs/studio/overview).
- **Studio reads the project's `.env` files again when you save one.** The config loads again with the new values, so a source's `baseURL`, the graph and the mocks follow without a restart. A file created after Studio started counts too. A variable the files no longer set is removed, one the process was started with keeps its value, and the log names the variables that changed, never their values. See [How Studio loads the project](https://courier.noverax.cloud/docs/studio/project-loading).
- **An import with a proxy caller marks its API for pages.** Its `source.ts` says `expose: true`, and its `proxy.ts` takes the import's routes from the project's routes module, so it reads the same whichever endpoints **Manage** adds or removes.
- **A mock refuses at its proxy routes what your proxy refuses** — an endpoint no mark opens, a GET to anything but a read, or to a read whose variables stay out of the address — with the proxy's status and its body, `{ "success": false, "message": … }`, so a page that works against the mock is not refused once it calls the proxy, and reads a refusal as the proxy writes it.
- The VS Code extension's `courier-routes` snippet writes routes by hand where Courier writes none, in place of `courier-boundary`.
- `create-courier` marks its example API, and where a page calls the API through your server it adds `courier.routes.ts`, `@noverax/courier-cli` and a `routes` script that writes the module again without Studio.

### Smaller pages

- **A page no longer bundles code only a server runs.** The terminal logger, the chain of addresses a request came through and the check of `forward` stay out of a page's bundle. A bundler that builds for the browser takes a light stand-in for each through the package's `imports` field, while Node, edge runtimes and React Native take the modules themselves. At start, a page's direct caller loads 33.4 KiB gzipped, about 6 KiB less than in 0.2, and a proxy caller with its routes 15.6 KiB, about 2 KiB less.
- **Your bundler needs to read a package's `imports` field**, as Vite, webpack 5, Rollup, esbuild, Turbopack and Metro do. See [Requirements](https://courier.noverax.cloud/docs/installation#requirements).

### Fixes

- **React Query hooks work in older browsers when a call passes its own `signal`.** In Safari before 17.4, Chrome before 116 and Firefox before 124, such a query threw a `TypeError`.
- **Asking an API for its double-submit token no longer logs a false failure in older browsers.** In Safari before 17, Chrome before 113 and Firefox before 112, reading the answer's cookies threw after the token had arrived, and the log said that asking had failed.
- **A WebSocket subscription finds its source by the names your sources declare alone**, as a call and a stream do; a topic naming a member every object has is refused by its name.

## [0.2.0](https://github.com/NoveraX/courier/compare/v0.1.0...v0.2.0) (2026-10-14)

Identical reads now go out as one request, a browser's headers no longer replace your API's own, and your API learns the user's address from every framework.

### Breaking change

`deduplicate` is removed from `defineApi` and `createProxyCaller`. Under that name a newer call cancelled the older one to the same endpoint, whatever its variables. That is now `cancelPrevious`, which lists the reads it applies to and is checked where the API is defined:

```ts
// 0.1
createProxyCaller<typeof api>("api", { boundary, deduplicate: true })

// 0.2
createProxyCaller<typeof api>("api", { boundary, cancelPrevious: ["users.search"] })
```

To stop sending the same read twice, you no longer need this option: identical reads share one request, as described below. In Studio's events, `dedup:*` is now `call:superseded`. See [Cancelling the previous call](https://courier.noverax.cloud/docs/advanced/abort#cancelling-the-previous-call).

### One request for identical reads

- **Identical reads made at the same moment share one request.** It does not matter whether two components or two places of a page make them. Each call gets an answer of its own. This works in the browser, on the server, in React Native and through the proxy. Identical means every part of the request, including the credentials and the user's address, so a user never gets another's answer. Writes, streams and calls that follow their progress always go alone, and `coalesce: false` sends a call, an API or a proxy client's calls alone. See [Identical reads share one request](https://courier.noverax.cloud/docs/advanced/abort#identical-reads-share-one-request).
- **In Next.js, `createServerCaller` sends a read once per render.** `generateMetadata` and the page share it. See [One read per render](https://courier.noverax.cloud/docs/frameworks/nextjs#one-read-per-render).
- **`cacheMiddleware` fetches a missed entry once.** It sends one request however many callers miss that entry at once.

### Security

- **The browser can no longer override your API's headers.** A header the browser sends through the proxy, such as `Authorization`, `Referer` or `X-Request-Id`, no longer replaces one your API sets in its `headers`. The session, the call, middleware and an endpoint's own closure still apply after them.
- **The proxy can limit how often one caller calls it.** Set `rateLimit` for this. It uses GCRA, answers with `RateLimit` headers and keeps its counts in memory or in Redis through `@noverax/courier-redis`. `browsersOnly` refuses calls that carry none of a browser's marks. See [Rate limits](https://courier.noverax.cloud/docs/proxy-mode/overview#rate-limits).
- **`defineBoundary` is checked against the API it belongs to.** An exposed path stops the API where it is defined if it does not exist or has another shape. So does a `sensitive` list that disagrees with the endpoints' `sensitiveVariables`.

### The user's address and request id

- **Every adapter now passes the user's address to your API.** `X-Forwarded-For` grows as a chain, as nginx writes it.
- **You can name the headers your backend reads.** `forward.clientAddress` and `forward.requestId` take names such as `x-real-ip` or `x-request-id`. `COURIER_TRUSTED_PROXIES` names the proxies in front of you, and `COURIER_CLIENT_ADDRESS_HEADER` names the header a CDN writes. See [The user's address](https://courier.noverax.cloud/docs/deployment/overview#the-users-address).
- **Request ids from proxies and platforms are kept.** Before, the ids Kong, AWS and Google Cloud write were replaced with random ones.

### Defining APIs

- **`.defaults()` gives an endpoint's variables default values.** In `.defaults({ groupBy: "year" })`, the key becomes optional and the caller's value wins. Studio, OpenAPI and agents' tools show the default. See [Default variables](https://courier.noverax.cloud/docs/core-concepts/defining-apis#default-variables).

### Studio

- **Search a call's answer, variables and headers.** Matches are highlighted, Enter and Shift+Enter step through them, and a value's path copies as `data.cities[41].name`.
- **Studio reads the project's `.env` files before `courier.config.ts`, as your dev server does.** Use `--dotenv` to name other files.
- **Studio shows where each attached app runs.**
- **Spec jobs and formatters run in processes of their own.** Each process has a memory cap and ends when Studio does. An import's code is generated without parsing it again.
- The VS Code extension is now Courier Studio.
- Docs opens the documentation, the Explorer graph's cards no longer touch, and Courier's snippets carry its mark.

### Compatibility

- **The core runs in Safari 15.4, Chrome 97, Firefox 104 and newer.** It also runs on a page served over plain HTTP and in React Native: it no longer calls `URL.canParse` or needs `crypto.subtle`. See [Requirements](https://courier.noverax.cloud/docs/installation#requirements).
- **The core's JavaScript is published as one file per module.** A page's proxy client loads about a third less at start, and stack traces name the module.
- **Projects on `"moduleResolution": "node"` resolve every subpath.** `create-courier` lists what TypeScript 6 deprecates in your `tsconfig.json`.
- **SSE streams run in the Next.js Edge Runtime.**
- `create-courier` loads Studio's `next.config` wrapper in `next dev` only, so `next start` runs without dev dependencies. It also keeps a CRLF file's line ends.

All nineteen packages move to 0.2.0.

## [0.1.0](https://github.com/NoveraX/courier/compare/v0.0.0...v0.1.0) (2026-10-13)

Courier's first public release.

**Type-safe HTTP for any framework.** Define your API once in plain TypeScript, then call it from server code, or from the browser through a proxy that keeps your keys and sessions on the server, over HTTP, SSE and WebSockets. Mock it, watch every call in Studio, and hand it to AI agents as tools. No codegen, no schema files, and any backend that speaks HTTP.

### Get started

```bash
npx @noverax/create-courier
```

Run it in a Next.js, Nuxt, SvelteKit, Astro, React Router, Remix, SolidStart, React or Vue (Vite), Expo, Express, Hono, Fastify or NestJS project. It shows its plan first and replaces nothing of yours: it adds a typed example API, the route the browser calls it through, `courier.config.ts`, a mock and a page at `/courier`, installs the packages with your package manager and type-checks what it added.

Read the [documentation](https://courier.noverax.cloud) or try Studio in the [live demo](https://demo.courier.noverax.cloud).

### The client

`@noverax/courier` types every call from the definition, endpoint names, variables and answers alike, and checks them at runtime with Zod, Valibot, ArkType or any Standard Schema library.

- **Server code calls the API directly.** The browser goes through a proxy, and [`defineBoundary`](https://courier.noverax.cloud/docs/proxy-mode/boundary) names the endpoints a page may call; the API's address, paths and middleware never ship with the page.
- **Streams and channels end well.** SSE streams and WebSocket channels complete, fail or reconnect as the server says, and a shutdown tells each client when to come back.
- **Everything around the call.** Middleware for retries, auth with token refresh, caching, rate limits and logging; user sessions with CSRF protection; corporate proxies and mutual TLS; typed webhooks for Stripe, GitHub, Standard Webhooks or your own HMAC; OpenAPI export; and logs a pipeline reads, as text or JSON.

### Framework adapters

Next.js, with an App Router route and Server Actions, Nuxt, SvelteKit, Astro, React Router and Remix, SolidStart, Express, Fastify, Hono on Node.js, Bun, Deno or Cloudflare Workers, and NestJS. Each is one route that proxies typed calls with the user's session. `@noverax/courier-react` adds TanStack Query hooks typed from the same definition, with live SSE and WebSocket hooks.

### Running it

- `@noverax/courier-server` runs the proxy on its own port, for static and serverless front ends, Docker and Kubernetes, with health and readiness checks, body limits and graceful shutdown.
- `@noverax/courier-redis` carries channels, presence and stream history across replicas.

### Studio and mocks

- `@noverax/courier-studio` shows every request your app makes, live, in a timeline, an inspector and a playground. It imports OpenAPI specifications, finds where your API and its schemas drift apart, turns recorded calls into tests with `courier-studio verify`, and reports breaking changes on a pull request with `courier-studio diff`. It runs on your machine and stays off in production.
- `@noverax/courier-mock` serves mock APIs from the same definition, with typed handlers, a SQLite-backed store, scenarios, network conditions and faults, contract tests and fixtures.

### Your API for AI agents

`@noverax/courier-mcp` offers your API to AI agents as tools over stdio and Streamable HTTP. Only the endpoints you mark are offered, every call goes through your middleware, and a person confirms what cannot be undone.

### In your editor

Courier for VS Code shows every endpoint and how its calls went above each call, opens Studio beside your code and runs your recorded tests. Courier File Icons gives `courier.config.ts`, `courier.mocks.ts` and the `.courier` folder their own icons. Both are on [Open VSX](https://open-vsx.org/namespace/noverax), for VS Code, Cursor, Windsurf and VSCodium.

### Requirements

Node.js 22 or newer. Every change is tested on Linux, macOS and Windows; on Node.js 22, 24 and 26; in Chromium, Firefox and WebKit; against 25 framework versions; and in React Native through Expo.

All nineteen packages are published under `@noverax` at 0.1.0. Until 1.0, a breaking change raises the minor version.
