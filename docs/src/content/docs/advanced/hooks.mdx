## Overview

Nexus provides three lifecycle hooks that let you intercept requests at different stages. Hooks are defined in `BaseOptions` when creating a `Request` class, so they apply to every method in that source.

The execution order is:

1. `onRequest` — runs before the HTTP call. Can modify the request info.
2. The HTTP method executes.
3. On success: `onResponse` — can transform the response data or status.
4. On failure: `onError` — for logging and monitoring. Cannot recover the request.

## Hook signatures

All hooks receive a `HookInfo` object identifying the request. The return value determines whether the hook modifies anything:

- Return a modified object to apply changes.
- Return `undefined` to skip (no changes).

```ts title="types"
type HookInfo = {
  source: string
  group?: string
  query: string
  variables?: unknown
}

type BaseOptions = {
  // Called before the request is executed
  onRequest?: (info: HookInfo) => HookInfo | undefined | Promise<HookInfo | undefined>

  // Called after a successful response
  onResponse?: (
    info: HookInfo,
    response: { status: number; data: unknown }
  ) => { status: number; data: unknown } | undefined | Promise<...>

  // Called when a request fails (catch-safe)
  onError?: (info: HookInfo, error: HTTPError) => undefined | Promise<undefined>
}
```

## onRequest

Runs before the HTTP call. Receives `HookInfo` and can return a modified copy to change the source, group, query, or variables. Return `undefined` to proceed without changes.

Use cases: injecting auth tokens, redirecting to a different method, adding default variables, request logging.

```ts title="api/sources.ts"
class MyApi extends Request<typeof groups> {
  constructor() {
    super({
      baseURL: process.env.API_URL ?? "http://localhost:4000",
      groups,
      onRequest(info) {
        // Inject an auth token into variables for server-side requests
        const token = getAuthToken()
        return {
          ...info,
          variables: { ...info.variables, _authToken: token },
        }
      },
    })
  }
}
```

## onResponse

Runs after a successful response. Receives `HookInfo` and the `{ status, data }` object. Return a modified response to transform the data, or `undefined` to pass it through unchanged.

A common pattern is unwrapping API envelopes so your components receive clean data:

```ts title="api/sources.ts"
// Many APIs wrap responses in a { data } envelope:
// GET /users → { data: [{ id: 1, name: "Jane" }], meta: { total: 42 } }

class MyApi extends Request<typeof groups> {
  constructor() {
    super({
      baseURL: process.env.API_URL ?? "http://localhost:4000",
      groups,
      onResponse(_info, response) {
        // Unwrap the envelope — components receive the inner data directly
        if (response.data && typeof response.data === "object" && "data" in response.data) {
          return { status: response.status, data: response.data.data }
        }
        return undefined
      },
    })
  }
}
```

## onError

Runs when a request fails with an `HTTPError`. This hook is **catch-safe** — if your error handler itself throws, the exception is silently caught and does not propagate. This makes it safe for logging and analytics integrations.

```ts title="api/sources.ts"
import * as Sentry from "@sentry/nextjs"

class MyApi extends Request<typeof groups> {
  constructor() {
    super({
      baseURL: process.env.API_URL ?? "http://localhost:4000",
      groups,
      onError(info, error) {
        Sentry.captureException(error, {
          tags: {
            source: info.source,
            group: info.group,
            query: info.query,
          },
          extra: { variables: info.variables },
        })
        // onError is catch-safe — if Sentry throws, it won't crash your app
      },
    })
  }
}
```

<Callout variant="warning" title="onError cannot recover requests">
The `onError` hook is for observation only. You cannot retry or recover the request from this hook. Use `retry` in [Options](/docs/advanced/options) for automatic retries.
</Callout>

## Full logging example

Combine all three hooks to create a complete request logging pipeline:

```ts title="api/sources.ts"
// api/sources.ts
class MyApi extends Request<typeof groups> {
  constructor() {
    super({
      baseURL: process.env.API_URL ?? "http://localhost:4000",
      groups,
      onRequest(info) {
        console.log(`[${info.source}] ${info.group}:${info.query}`, info.variables)
        return undefined // don't modify the request
      },
      onResponse(info, response) {
        console.log(`[${info.source}] ${info.group}:${info.query} → ${response.status}`)
        return undefined // don't modify the response
      },
      onError(info, error) {
        console.error(`[${info.source}] ${info.group}:${info.query} failed:`, error.message)
      },
    })
  }
}
```

<Callout variant="tip" title="Hooks are async-compatible">
All hooks can be `async` functions. Nexus awaits the return value before proceeding to the next stage.
</Callout>
